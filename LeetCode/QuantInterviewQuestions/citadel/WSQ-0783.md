> [!example] Question 783 · Citadel
> ## Software Engineer Interview

Write a program to schedule a stream of pizza delivery orders.

[Source](https://www.thewallstreetquants.com/ebook#p=784)

> [!success]- Solution (Click to expand)
> ## Solution
>
> To schedule a stream of pizza delivery orders, process orders in the order they arrive and assign each one to the earliest available delivery resource. This is a standard online scheduling problem.
>
> A practical model is:
>
> - Each order has:
>   - an arrival time $a_i$
>   - a delivery duration $d_i$
> - A delivery driver becomes free after finishing the assigned order.
> - For each incoming order, assign it to the driver who becomes available earliest.
> - If no driver is free at time $a_i$, the order waits until the earliest driver is free.
>
> This can be implemented efficiently with a priority queue (min-heap) storing driver availability times.
>
> ### Approach
>
> Maintain a min-heap of pairs:
>
> $$
> (\text{next\_free\_time}, \text{driver\_id})
> $$
>
> For each order:
>
> 1. Extract the driver with minimum next free time.
> 2. The order starts at
>    $$
>    s_i = \max(a_i, \text{next\_free\_time})
>    $$
> 3. The order finishes at
>    $$
>    f_i = s_i + d_i
>    $$
> 4. Push the driver back into the heap with updated availability $f_i$.
>
> If the number of drivers is fixed, initialize the heap with all drivers available at time $0$.
>
> ### Correctness
>
> At each step, assigning the order to the earliest available driver minimizes the start time of that order among all possible driver assignments. Since only current and future availability matters in the online setting, this greedy choice is optimal for minimizing immediate waiting time and produces a valid schedule.
>
> ### Complexity
>
> Let $n$ be the number of orders and $k$ the number of drivers.
>
> Each order performs one heap pop and one heap push, each taking $O(\log k)$ time. Therefore:
>
> $$
> \text{Time} = O(n \log k)
> $$
>
> The heap stores $k$ drivers, so:
>
> $$
> \text{Space} = O(k)
> $$
>
> ## Program
>
> ```python
> import heapq
>
> def schedule_pizza_orders(orders, num_drivers):
>     """
>     orders: list of tuples (arrival_time, delivery_duration)
>     num_drivers: number of available drivers
>
>     Returns a list of schedules:
>     (order_id, driver_id, start_time, finish_time)
>     """
>     # Initialize all drivers as free at time 0
>     heap = [(0, driver_id) for driver_id in range(num_drivers)]
>     heapq.heapify(heap)
>
>     schedule = []
>
>     for order_id, (arrival_time, duration) in enumerate(orders):
>         next_free_time, driver_id = heapq.heappop(heap)
>
>         start_time = max(arrival_time, next_free_time)
>         finish_time = start_time + duration
>
>         schedule.append((order_id, driver_id, start_time, finish_time))
>
>         heapq.heappush(heap, (finish_time, driver_id))
>
>     return schedule
>
>
> # Example usage
> if __name__ == "__main__":
>     orders = [
>         (0, 30),
>         (5, 20),
>         (10, 25),
>         (15, 10),
>         (20, 15)
>     ]
>     num_drivers = 2
>
>     result = schedule_pizza_orders(orders, num_drivers)
>
>     for order_id, driver_id, start_time, finish_time in result:
>         print(
>             f"Order {order_id}: Driver {driver_id}, "
>             f"start = {start_time}, finish = {finish_time}"
>         )
> ```
>
> ## Example
>
> For orders
>
> $$
> [(0,30), (5,20), (10,25), (15,10), (20,15)]
> $$
>
> with $2$ drivers, the program may produce:
>
> - Order $0$ $\to$ Driver $0$, start $0$, finish $30$
> - Order $1$ $\to$ Driver $1$, start $5$, finish $25$
> - Order $2$ $\to$ Driver $1$, start $25$, finish $50$
> - Order $3$ $\to$ Driver $0$, start $30$, finish $40$
> - Order $4$ $\to$ Driver $0$, start $40$, finish $55$
>
> Thus, the stream of pizza delivery orders is scheduled efficiently in $O(n \log k)$ time.
