> [!example] Question 754 · Citadel
> ## Software Engineer Intern Interview

How would you solve a scheduling issue given a directed acyclic graph (DAG) of tasks and k computers? What if k is one or infinity?

[Source](https://www.thewallstreetquants.com/ebook#p=755)

> [!success]- Solution (Click to expand)
> ## Scheduling a DAG of tasks on $k$ computers
>
> Let the tasks form a directed acyclic graph $G = (V,E)$, where:
>
> - each node is a task,
> - an edge $u \to v$ means task $v$ cannot start until $u$ finishes,
> - each task has processing time $p_v$.
>
> The goal is to minimize the **makespan**, i.e. the finishing time of the last task, on $k$ identical computers.
>
> This is a classic precedence-constrained scheduling problem.
>
> ### 1. General case: arbitrary $k$
>
> For general $k \ge 2$, the problem is computationally hard in general. A standard way to think about it is:
>
> - At any time, a task is **available** if all its predecessors have completed.
> - Whenever a machine becomes free, choose one available task to run.
> - Continue until all tasks are finished.
>
> The difficulty is that the order among available tasks matters.
>
> #### Important lower bounds
>
> Any schedule must have makespan at least
>
> $$
> \max\left\{ \frac{\sum_{v \in V} p_v}{k},\; L \right\},
> $$
>
> where $\sum_{v \in V} p_v$ is the total work, and $L$ is the length of the **critical path**, i.e. the maximum total processing time along any directed path in the DAG. These are fundamental: even with perfect parallelism, $k$ machines must process all the work, and precedence constraints force at least the critical path length regardless of how many machines are available.
>
> #### How to produce a schedule
>
> A standard practical algorithm is **list scheduling**:
>
> 1. Compute the set of currently available tasks.
> 2. Maintain a priority rule, for example largest processing time first, or largest bottom-level first, where the bottom-level of task $v$ is
>    $$
>    b(v) = p_v + \max_{(v,w)\in E} b(w),
>    $$
>    with sinks having $b(v)=p_v$.
> 3. Whenever a machine is free, assign the highest-priority available task.
>
> This gives a valid schedule, though not always optimal.
>
> #### Complexity
>
> Finding the optimal schedule for general $k$ is NP-hard. So in an interview, the key is usually to recognize the DAG structure, state the lower bounds, mention list scheduling or priority scheduling, and note the hardness of exact optimization in general.
>
> ### 2. Special case: $k = \infty$
>
> If there are infinitely many computers, there is no resource contention. The only constraints are precedence constraints, so each task can start as soon as all its predecessors finish.
>
> Define the earliest finish time recursively:
>
> $$
> EF(v) = p_v + \max_{u \in \operatorname{pred}(v)} EF(u),
> $$
>
> with the convention that if $v$ has no predecessors, then
>
> $$
> EF(v) = p_v.
> $$
>
> Then the optimal makespan is
>
> $$
> \max_{v \in V} EF(v),
> $$
>
> which is exactly the **critical path length**.
>
> #### Algorithm
>
> 1. Topologically sort the DAG.
> 2. Process nodes in topological order.
> 3. For each node $v$, compute
>    $$
>    ES(v) = \max_{u \in \operatorname{pred}(v)} EF(u),
>    $$
>    with $ES(v)=0$ for source nodes.
> 4. Then set $EF(v) = ES(v) + p_v$.
>
> This runs in linear time:
>
> $$
> O(|V| + |E|).
> $$
>
> With unlimited machines, the optimal schedule is to run every task as early as possible, and the answer is the critical path length.
>
> ### 3. Special case: $k = 1$
>
> With one computer, tasks must run one at a time. Since the graph is acyclic, any **topological ordering** gives a feasible schedule.
>
> Moreover, with only one machine, there is no parallelism anyway, so the makespan is simply the total work:
>
> $$
> \sum_{v \in V} p_v.
> $$
>
> The precedence constraints only restrict the order, not the total completion time. The algorithm is simply to compute any topological ordering of the DAG and execute tasks in that order on the single machine. This is optimal, and the makespan is
>
> $$
> C_{\max} = \sum_{v \in V} p_v.
> $$
>
> ### 4. Summary
>
> Given a DAG of tasks with processing times and $k$ identical computers:
>
> If $k=1$, any topological ordering is optimal, with makespan
> $$
> \sum_{v \in V} p_v.
> $$
>
> If $k=\infty$, start each task as soon as all predecessors finish; the makespan equals the critical path length,
> $$
> \max_{\text{directed paths } P} \sum_{v \in P} p_v.
> $$
>
> If $k$ is general, the optimal problem is NP-hard. Use the lower bound
> $$
> \max\left\{ \frac{\sum_{v\in V} p_v}{k},\; \text{critical path length} \right\},
> $$
> together with a standard heuristic such as list scheduling based on available tasks and priorities like longest remaining path.
>
> If the interviewer wants an implementation-oriented answer, the cleanest practical response is to compute indegrees, use a queue or priority queue of available tasks, repeatedly assign available tasks to free machines, and update successors when their prerequisites complete.
