> [!example] Question 784 · Citadel
> ## Software Developer Interview

Given an 8x8 chessboard, write code to calculate the number of ways to go from the top left corner to the bottom right corner, given that you can move down, up, left, and right.

[Source](https://www.thewallstreetquants.com/ebook#p=785)

> [!success]- Solution (Click to expand)
> ## Solution
>
> If moves in all four directions are allowed, the answer depends on whether revisiting squares is permitted.
>
> - If revisiting squares is allowed, then there are **infinitely many** ways: one can always insert back-and-forth loops before eventually reaching the bottom-right corner.
> - Therefore, the meaningful finite interpretation is usually:
>
> Count the number of **simple paths** from the top-left square to the bottom-right square on an $8 \times 8$ grid, where each square is visited at most once.
>
> This can be computed by depth-first search with backtracking.
>
> ### Idea
>
> Model the chessboard as a graph:
>
> - each square is a vertex,
> - edges connect orthogonally adjacent squares.
>
> Then recursively explore all paths from $(0,0)$ to $(7,7)$, marking a square as visited when entering it and unmarking it when backtracking.
>
> ### Python code
>
> ```python
> def count_paths_8x8():
>     n = 8
>     target = (n - 1, n - 1)
>     visited = [[False] * n for _ in range(n)]
>
>     directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]
>
>     def dfs(r, c):
>         if (r, c) == target:
>             return 1
>
>         visited[r][c] = True
>         total = 0
>
>         for dr, dc in directions:
>             nr, nc = r + dr, c + dc
>             if 0 <= nr < n and 0 <= nc < n and not visited[nr][nc]:
>                 total += dfs(nr, nc)
>
>         visited[r][c] = False
>         return total
>
>     return dfs(0, 0)
>
> print(count_paths_8x8())
> ```
>
> ### Explanation
>
> At each square $(r,c)$:
>
> 1. If $(r,c) = (7,7)$, one valid path has been completed, so return $1$.
> 2. Otherwise, mark $(r,c)$ as visited.
> 3. Try moving in each of the four directions:
>    - down: $(r+1,c)$
>    - up: $(r-1,c)$
>    - right: $(r,c+1)$
>    - left: $(r,c-1)$
> 4. Recurse only if the new square is inside the board and unvisited.
> 5. After exploring, unmark $(r,c)$ so other paths may use it.
>
> ### Complexity
>
> This brute-force search is exponential in the number of squares, since it enumerates all simple paths. For an $8 \times 8$ board, the total number is extremely large, so this program may take a very long time to finish.
>
> ### If revisiting squares is allowed
>
> Then the number of ways is not finite. For example, from any reachable square one may move right then left repeatedly any number of times before continuing to the destination. Hence the number of paths is
>
> $$
> \infty.
> $$
>
> Thus:
>
> - **with revisits allowed:** infinitely many paths;
> - **without revisits allowed:** use the backtracking code above to count all simple paths.
