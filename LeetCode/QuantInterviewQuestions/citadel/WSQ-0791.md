> [!example] Question 791 · Citadel
> ## Quantitative Research Analyst Interview

You are given an array of integers, which may include both negative and positive values, and another integer S. Find three different integers in the array whose sum is closest to S. If multiple solutions exist, any is acceptable. Is there an algorithm to find the three integers in O(n^2) time?

[Source](https://www.thewallstreetquants.com/ebook#p=792)

> [!success]- Solution (Click to expand)
> ## Solution
>
> Yes. There is an $O(n^2)$ algorithm based on sorting and the two-pointer technique.
>
> ### Idea
>
> First sort the array. Then fix one element $A_i$ and reduce the problem to:
>
> - find two elements among the remaining entries whose sum is as close as possible to $S - A_i$.
>
> Because the array is sorted, this two-sum-closest subproblem can be solved in linear time using two pointers. Repeating this for each $i$ gives total time $O(n^2)$.
>
> ---
>
> ## Algorithm
>
> Let the sorted array still be denoted by $A[0], A[1], \dots, A[n-1]$.
>
> 1. Sort $A$.
> 2. Initialize:
>    - best triple indices or values,
>    - best difference $d = \infty$.
> 3. For each $i$ from $0$ to $n-3$:
>    - Set two pointers:
>      - $l = i+1$,
>      - $r = n-1$.
>    - While $l < r$:
>      - Compute
>        $$
>        \text{sum} = A[i] + A[l] + A[r].
>        $$
>      - If
>        $$
>        |\text{sum} - S| < d,
>        $$
>        update the best triple and set
>        $$
>        d = |\text{sum} - S|.
>        $$
>      - If $\text{sum} = S$, return this triple immediately, since no closer sum is possible.
>      - If
>        $$
>        \text{sum} < S,
>        $$
>        increase $l$ by $1$ to make the sum larger.
>      - Otherwise decrease $r$ by $1$ to make the sum smaller.
>
> ---
>
> ## Pseudocode
>
> ```text
> ThreeSumClosest(A, S):
>     sort(A)
>     n = length(A)
>
>     bestSum = A[0] + A[1] + A[2]
>     bestTriple = (A[0], A[1], A[2])
>
>     for i = 0 to n - 3:
>         l = i + 1
>         r = n - 1
>
>         while l < r:
>             curr = A[i] + A[l] + A[r]
>
>             if |curr - S| < |bestSum - S|:
>                 bestSum = curr
>                 bestTriple = (A[i], A[l], A[r])
>
>             if curr == S:
>                 return bestTriple
>             else if curr < S:
>                 l = l + 1
>             else:
>                 r = r - 1
>
>     return bestTriple
> ```
>
> ---
>
> ## Correctness intuition
>
> For a fixed $i$, the array portion $A[i+1 \dots n-1]$ is sorted.
>
> - If the current sum
>   $$
>   A[i] + A[l] + A[r]
>   $$
>   is too small, then decreasing $r$ would only make it smaller, so the only useful move is to increase $l$.
> - If the current sum is too large, then increasing $l$ would only make it larger, so the only useful move is to decrease $r$.
>
> Thus the two-pointer scan examines all candidates that could improve the answer for that fixed $i$ without missing the optimal pair. Since this is done for every $i$, the algorithm finds a triple whose sum is closest to $S$.
>
> ---
>
> ## Running time
>
> - Sorting takes $O(n \log n)$.
> - The outer loop runs $O(n)$ times.
> - For each fixed $i$, the two pointers move inward at most $O(n)$ total steps.
>
> Hence the total running time is
>
> $$
> O(n \log n) + O(n^2) = O(n^2).
> $$
>
> The extra space is $O(1)$ beyond the space used by sorting (if sorting is done in place).
>
> ---
>
> ## Final answer
>
> Yes. Sort the array and, for each fixed first element, use a two-pointer search on the remaining suffix to find the pair that makes the three-element sum closest to $S$. This yields an $O(n^2)$ algorithm.
