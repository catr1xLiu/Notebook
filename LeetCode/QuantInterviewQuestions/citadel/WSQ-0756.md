> [!example] Question 756 · Citadel
> ## Software Developer Intern Interview

If a Binary Search Tree was implemented incorrectly such that a node has a left child that is not smaller than itself, how would you detect this violation? What is the most efficient method to identify this issue?

[Source](https://www.thewallstreetquants.com/ebook#p=757)

> [!success]- Solution (Click to expand)
> ## Checking Whether a Binary Search Tree Is Valid
>
> A Binary Search Tree (BST) must satisfy the rule:
>
> - every value in the left subtree of a node is **strictly smaller** than the node’s value,
> - every value in the right subtree is **strictly larger** than the node’s value,
>
> and this must hold for **every node**, not just its immediate children.
>
> ### Why a simple child check is not enough
>
> It is not sufficient to check only:
>
> - left child $<$ node
> - right child $>$ node
>
> because a violation can occur deeper in a subtree.
>
> For example:
>
> - root $= 10$
> - left child $= 5$
> - right child of $5$ is $12$
>
> Here, $12 > 5$ is locally fine, but $12$ is in the left subtree of $10$, so it should also satisfy $12 < 10$, which it does not. Thus the tree is not a BST.
>
> ---
>
> ## Most efficient method: range checking
>
> The standard efficient method is to traverse the tree while carrying the valid range of values each node is allowed to have.
>
> ### Idea
>
> For each node, keep:
>
> - a lower bound,
> - an upper bound.
>
> Initially, the root may have no bounds.
>
> Then:
>
> - when going to the left child of a node with value $v$, the upper bound becomes $v$,
> - when going to the right child, the lower bound becomes $v$.
>
> If any node violates its allowed range, the tree is invalid.
>
> ---
>
> ## Algorithm
>
> For each node with value $x$:
>
> 1. If there is a lower bound and $x \le \text{lower}$, return false.
> 2. If there is an upper bound and $x \ge \text{upper}$, return false.
> 3. Recursively check:
>    - left subtree with range $(\text{lower}, x)$
>    - right subtree with range $(x, \text{upper})$
>
> If all nodes satisfy their ranges, the tree is a valid BST.
>
> ---
>
> ## Pseudocode
>
> ```text
> isValidBST(node, lower, upper):
>     if node is null:
>         return true
>
>     if lower is not null and node.value <= lower:
>         return false
>
>     if upper is not null and node.value >= upper:
>         return false
>
>     return isValidBST(node.left, lower, node.value)
>            and
>            isValidBST(node.right, node.value, upper)
> ```
>
> Call it as:
>
> ```text
> isValidBST(root, null, null)
> ```
>
> ---
>
> ## Time and space complexity
>
> Each node is visited exactly once, so the time complexity is
>
> $$O(n)$$
>
> where $n$ is the number of nodes.
>
> The extra space is due to recursion depth:
>
> - average case: $$O(\log n)$$ for a balanced tree,
> - worst case: $$O(n)$$ for a completely skewed tree.
>
> This is optimal, because in the worst case you must inspect every node to be certain the tree is valid.
>
> ---
>
> ## Alternative method: inorder traversal
>
> Another correct approach is to perform an inorder traversal. For a valid BST, inorder traversal must produce values in **strictly increasing order**.
>
> Thus:
>
> 1. Traverse left subtree,
> 2. visit node,
> 3. traverse right subtree,
>
> and check that each visited value is larger than the previous one.
>
> This also runs in
>
> $$O(n)$$
>
> time.
>
> ---
>
> ## Conclusion
>
> The most efficient way to detect whether a BST was written incorrectly is to traverse the tree once and verify that each node lies within its allowed value range. This catches errors anywhere in the tree, not just between parent and child, and runs in optimal time:
>
> $$O(n)$$
