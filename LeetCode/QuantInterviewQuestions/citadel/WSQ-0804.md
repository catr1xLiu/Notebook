> [!example] Question 804 · Citadel
> ## Senior Software Engineer Interview

In C++ templates, in what cases is the keyword 'typename' used?

[Source](https://www.thewallstreetquants.com/ebook#p=805)

> [!success]- Solution (Click to expand)
> In C++, the keyword `typename` is used in templates primarily in two situations.
>
> ## 1. To declare a template type parameter
>
> When defining a template, `typename` can introduce a type parameter:
>
> ```cpp
> template <typename T>
> class Box {
>     T value;
> };
> ```
>
> This is equivalent to:
>
> ```cpp
> template <class T>
> class Box {
>     T value;
> };
> ```
>
> Here, `typename` and `class` mean the same thing for a template type parameter.
>
> ---
>
> ## 2. To tell the compiler that a dependent name is a type
>
> Inside a template, some names depend on a template parameter. The compiler cannot always know whether such a name refers to a type or something else. In those cases, `typename` is required.
>
> Example:
>
> ```cpp
> template <typename T>
> void f() {
>     typename T::value_type x;
> }
> ```
>
> If `T` is a type that contains a nested type named `value_type`, then `T::value_type` is a *dependent name*. Without `typename`, the compiler does not assume it is a type.
>
> So this is required:
>
> ```cpp
> typename T::value_type
> ```
>
> not:
>
> ```cpp
> T::value_type
> ```
>
> ---
>
> ## When it is needed
>
> Use `typename` before a qualified dependent name when that name denotes a type, for example:
>
> ```cpp
> template <typename T>
> void g() {
>     typename T::iterator it;
>     typename T::const_iterator cit;
> }
> ```
>
> Since `T::iterator` and `T::const_iterator` depend on `T`, the compiler needs `typename` to parse them as types.
>
> ---
>
> ## When it is not needed
>
> ### 1. In a base class list
>
> ```cpp
> template <typename T>
> class Derived : public T::base_type {
> };
> ```
>
> Here `typename` is not allowed in the base-class list.
>
> ### 2. For non-dependent names
>
> ```cpp
> std::vector<int>::iterator it;
> ```
>
> This does not depend on a template parameter, so `typename` is unnecessary.
>
> ### 3. When the type is already introduced as a template parameter
>
> ```cpp
> template <typename T>
> void f(T x) {
> }
> ```
>
> No extra `typename` is needed for `T`.
>
> ---
>
> ## Common example
>
> ```cpp
> template <typename Container>
> void print_first(const Container& c) {
>     typename Container::const_iterator it = c.begin();
> }
> ```
>
> `Container::const_iterator` depends on `Container`, so `typename` is required.
>
> ---
>
> ## Summary
>
> The word `typename` is used:
>
> 1. To declare a template type parameter:
>    ```cpp
>    template <typename T>
>    ```
>
> 2. To indicate that a dependent qualified name is a type:
>    ```cpp
>    typename T::value_type
>    ```
>
> The key rule is:
>
> If a name inside a template depends on a template parameter and refers to a type, it usually must be prefixed by `typename`.
