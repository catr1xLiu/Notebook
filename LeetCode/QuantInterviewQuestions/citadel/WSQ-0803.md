> [!example] Question 803 · Citadel
> ## Senior Software Engineer Interview

In C++, would you prefer to store pointers or references in a vector? Explain your reasoning.

[Source](https://www.thewallstreetquants.com/ebook#p=804)

> [!success]- Solution (Click to expand)
> In a `std::vector`, one generally stores **pointers**, not **references**.
>
> ## Reason
>
> A C++ reference is **not an object**. It must be bound when created, cannot be reseated, and standard containers such as `std::vector` require their element type to be assignable/movable in ways that references do not satisfy. Thus a type like
>
> ```cpp
> std::vector<int&>
> ```
>
> is ill-formed.
>
> By contrast, pointers are ordinary objects, so a vector of pointers is valid:
>
> ```cpp
> std::vector<int*> v;
> ```
>
> ## Practical interpretation
>
> If you need a container that refers to existing objects without owning them, common choices are:
>
> - `std::vector<T*>` for raw pointers,
> - `std::vector<std::reference_wrapper<T>>` if you want reference-like semantics in a container.
>
> Example with `std::reference_wrapper`:
>
> ```cpp
> #include <vector>
> #include <functional>
>
> int a = 1, b = 2;
> std::vector<std::reference_wrapper<int>> v{a, b};
> ```
>
> ## Preference
>
> - Use **references** for function parameters and local aliases.
> - Use **pointers** or `std::reference_wrapper` for storage in containers.
> - If ownership is involved, prefer smart pointers such as `std::unique_ptr<T>` or `std::shared_ptr<T>`.
>
> ## Conclusion
>
> A `std::vector` should store **pointers** rather than references, because references cannot be stored directly in standard containers. If reference-like behavior is desired, use `std::reference_wrapper<T>`.
