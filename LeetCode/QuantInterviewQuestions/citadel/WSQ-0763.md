> ## Software Engineer Interview

Implement a balanced binary search tree from scratch, explain its time complexity, and optimize it to efficiently handle duplicate values.

[Source](https://www.thewallstreetquants.com/ebook#p=764)

> [!success]- Solution (Click to expand)
> ## Balanced Binary Search Tree with Duplicate Handling
>
> A suitable choice is an **AVL tree**, which is a self-balancing binary search tree. It maintains the property that for every node, the heights of the left and right subtrees differ by at most $1$. This guarantees logarithmic height and therefore efficient operations.
>
> To optimize for duplicate values, instead of storing equal keys as separate nodes, store a **count** in each node. Then repeated insertions of the same value simply increment the count, and deletions decrement it until the count reaches $0$.
>
> ---
>
> ## 1. Node Structure
>
> Each node stores:
>
> - the key
> - the number of times it appears
> - pointers to left and right children
> - the height of the subtree rooted at that node
>
> A typical node is:
>
> ```text
> Node:
>     key
>     count
>     height
>     left
>     right
> ```
>
> ---
>
> ## 2. AVL Tree Invariant
>
> For every node $v$, define its balance factor as
>
> $$
> \text{balance}(v) = \text{height}(v.\text{left}) - \text{height}(v.\text{right}).
> $$
>
> The AVL property requires
>
> $$
> |\text{balance}(v)| \le 1.
> $$
>
> If an insertion or deletion violates this condition, the tree is restored using rotations.
>
> ---
>
> ## 3. Core Operations
>
> ### Height Update
>
> If a node $v$ has children $L$ and $R$, then
>
> $$
> \text{height}(v) = 1 + \max(\text{height}(L), \text{height}(R)).
> $$
>
> A null child has height $0$.
>
> ---
>
> ## 4. Rotations
>
> ### Right Rotation
>
> Used when the left subtree becomes too heavy.
>
> If $y$ is unbalanced and $x = y.\text{left}$, then after a right rotation:
>
> - $x$ becomes the new root of the subtree
> - $y$ becomes the right child of $x$
> - $x$’s original right subtree becomes $y$’s left subtree
>
> ### Left Rotation
>
> Symmetric to right rotation.
>
> ### Double Rotations
>
> These occur when the heavy child leans in the opposite direction:
>
> - Left-Right rotation
> - Right-Left rotation
>
> ---
>
> ## 5. Insertion with Duplicate Optimization
>
> ### Idea
>
> To insert a value $k$:
>
> 1. Traverse the tree as in ordinary BST insertion.
> 2. If a node with key $k$ already exists, increment its count.
> 3. Otherwise, insert a new node with count $1$.
> 4. While unwinding recursion, update heights.
> 5. Rebalance if needed.
>
> ### Pseudocode
>
> ```python
> class Node:
>     def __init__(self, key):
>         self.key = key
>         self.count = 1
>         self.height = 1
>         self.left = None
>         self.right = None
>
>
> def height(node):
>     return node.height if node else 0
>
>
> def update(node):
>     node.height = 1 + max(height(node.left), height(node.right))
>
>
> def balance_factor(node):
>     return height(node.left) - height(node.right)
>
>
> def rotate_right(y):
>     x = y.left
>     t2 = x.right
>
>     x.right = y
>     y.left = t2
>
>     update(y)
>     update(x)
>     return x
>
>
> def rotate_left(x):
>     y = x.right
>     t2 = y.left
>
>     y.left = x
>     x.right = t2
>
>     update(x)
>     update(y)
>     return y
>
>
> def rebalance(node):
>     update(node)
>     bf = balance_factor(node)
>
>     if bf > 1:
>         if balance_factor(node.left) < 0:
>             node.left = rotate_left(node.left)
>         return rotate_right(node)
>
>     if bf < -1:
>         if balance_factor(node.right) > 0:
>             node.right = rotate_right(node.right)
>         return rotate_left(node)
>
>     return node
>
>
> def insert(node, key):
>     if not node:
>         return Node(key)
>
>     if key < node.key:
>         node.left = insert(node.left, key)
>     elif key > node.key:
>         node.right = insert(node.right, key)
>     else:
>         node.count += 1
>         return node
>
>     return rebalance(node)
> ```
>
> ---
>
> ## 6. Search
>
> Searching is identical to a standard BST search.
>
> - If $k < \text{node.key}$, go left.
> - If $k > \text{node.key}$, go right.
> - If equal, return the node and its count.
>
> ### Pseudocode
>
> ```python
> def search(node, key):
>     while node:
>         if key < node.key:
>             node = node.left
>         elif key > node.key:
>             node = node.right
>         else:
>             return node
>     return None
> ```
>
> If found, the frequency of the key is `node.count`.
>
> ---
>
> ## 7. Deletion with Duplicate Optimization
>
> ### Idea
>
> To delete a value $k$:
>
> 1. Search for the node.
> 2. If its count is greater than $1$, decrement the count and stop.
> 3. If its count is $1$, remove the node as in ordinary BST deletion:
>    - no child
>    - one child
>    - two children
> 4. After structural deletion, update heights and rebalance.
>
> ### Important Detail for Two-Child Deletion
>
> When deleting a node with two children, replace it with its inorder successor (smallest node in the right subtree) or predecessor. If counts are used, care must be taken not to lose multiplicities. One clean method is:
>
> - copy the successor’s key and count into the current node
> - then remove the successor node completely from the right subtree
>
> This requires a helper that removes a node regardless of count.
>
> ### Pseudocode
>
> ```python
> def min_value_node(node):
>     while node.left:
>         node = node.left
>     return node
>
>
> def delete_all_of_node(node, key):
>     if not node:
>         return None
>
>     if key < node.key:
>         node.left = delete_all_of_node(node.left, key)
>     elif key > node.key:
>         node.right = delete_all_of_node(node.right, key)
>     else:
>         if not node.left:
>             return node.right
>         if not node.right:
>             return node.left
>
>         succ = min_value_node(node.right)
>         node.key = succ.key
>         node.count = succ.count
>         node.right = delete_all_of_node(node.right, succ.key)
>
>     return rebalance(node) if node else None
>
>
> def delete(node, key):
>     if not node:
>         return None
>
>     if key < node.key:
>         node.left = delete(node.left, key)
>     elif key > node.key:
>         node.right = delete(node.right, key)
>     else:
>         if node.count > 1:
>             node.count -= 1
>             return node
>
>         if not node.left:
>             return node.right
>         if not node.right:
>             return node.left
>
>         succ = min_value_node(node.right)
>         node.key = succ.key
>         node.count = succ.count
>         node.right = delete_all_of_node(node.right, succ.key)
>
>     return rebalance(node) if node else None
> ```
>

> ## 8. Why This Handles Duplicates Efficiently
>
> If duplicates were inserted as separate nodes, many equal values could create unnecessary structure and complicate balancing. Storing duplicates in a count field gives several benefits:
>
> 1. **Less memory usage**: one node represents many equal values.
> 2. **Faster duplicate insertion**: finding the key is enough; no new structural changes are needed.
> 3. **Simpler ordering**: the BST invariant stays strict:
>    - left subtree keys are smaller
>    - right subtree keys are larger
>    - equality is handled inside the node
>
> Thus the tree height depends on the number of **distinct** keys, not the total number of inserted elements.
>
> If there are $n$ total elements but only $m$ distinct keys, then the tree height is
>
> $$
> O(\log m),
> $$
>
> not $O(\log n)$ with redundant duplicate nodes. This is a useful optimization when many repeated values occur.
>
> ---
>
> ## 9. Time Complexity
>
> Let $m$ be the number of distinct keys stored in the tree.
>
> Because an AVL tree maintains height
>
> $$
> O(\log m),
> $$
>
> all root-to-leaf traversals take logarithmic time.
>
> ### Search
>
> Search follows one path from the root downward, so its time complexity is
>
> $$
> O(\log m).
> $$
>
> ### Insertion
>
> Insertion consists of:
>
> 1. descending one path to the insertion point, which takes
>    $$
>    O(\log m),
>    $$
> 2. updating heights on the way back,
> 3. performing at most a constant number of rotations.
>
> Therefore insertion takes
>
> $$
> O(\log m).
> $$
>
> If the value is a duplicate already present in the tree, the algorithm still spends only
>
> $$
> O(\log m)
> $$
>
> to find the node, after which it merely increments the count.
>
> ### Deletion
>
> Deletion also follows one path, then possibly rebalances while returning upward. Each rebalance step is constant time, and there are at most $O(\log m)$ such steps. Hence deletion takes
>
> $$
> O(\log m).
> $$
>
> ### Space Complexity
>
> Each distinct key requires one node, so space usage is
>
> $$
> O(m).
> $$
>
> If duplicates are frequent, this is significantly smaller than storing all $n$ occurrences explicitly.
>
> ---
>
> ## 10. Summary
>
> A balanced BST can be implemented efficiently using an AVL tree. To optimize duplicate handling, each node stores a multiplicity count rather than creating multiple nodes with the same key.
>
> ### Final complexities
>
> - **Search:** $O(\log m)$
> - **Insert:** $O(\log m)$
> - **Delete:** $O(\log m)$
> - **Space:** $O(m)$
>
> where $m$ is the number of distinct keys.
>
> This design is both asymptotically efficient and practically well-suited for inputs containing many repeated values.
