> [!example] Question 812 · Citadel
> ## Software Engineer Intern Interview

How would you solve a scheduling issue given a directed acyclic graph (DAG) of tasks and k computers? What if k is one or infinity?

[Source](https://www.thewallstreetquants.com/ebook#p=813)

> [!success]- Solution (Click to expand)
> ## Scheduling a DAG of tasks on $k$ computers
>
> Let the tasks form a directed acyclic graph $G = (V, E)$, where each node is a task and an edge $u \to v$ means task $v$ cannot start until task $u$ finishes.
>
> Assume first that each task takes unit time. The goal is to minimize the total completion time, or **makespan**.
>
> ## Case 1: $k = \infty$
>
> If there are infinitely many computers, then any task can start as soon as all its prerequisites are done. So the only limitation is dependency structure.
>
> ### Key fact
>
> The optimal schedule length is the length of the **longest path** in the DAG, also called the **critical path**. No schedule can finish faster than the longest chain of dependencies, and with infinitely many machines, every task whose predecessors are complete can run immediately, so this lower bound is achievable.
>
> ### Algorithm
>
> Compute for each node $v$:
>
> $$
> dp[v] = 1 + \max_{u \to v} dp[u]
> $$
>
> with base case $dp[v] = 1$ if $v$ has no predecessors. Then the answer is
>
> $$
> \max_{v \in V} dp[v].
> $$
>
> This can be done in topological order in time
>
> $$
> O(|V| + |E|).
> $$
>
> ## Case 2: $k = 1$
>
> If there is only one computer, tasks must run one at a time. Since the graph is acyclic, there always exists a topological ordering, and executing tasks in any topological order is feasible.
>
> Because every task must be executed and only one runs at a time, the total time is simply the sum of task durations. For unit-time tasks, the optimal makespan is $|V|$; for general processing times $p_v$, the makespan is
>
> $$
> \sum_{v \in V} p_v.
> $$
>
> The dependencies affect which orders are legal, but not the total finishing time.
>
> ## Case 3: General $k$
>
> Now there are two constraints: precedence constraints from the DAG, and the restriction that at most $k$ tasks can run simultaneously. This problem is much harder.
>
> ### Important complexity fact
>
> For general $k \ge 2$, minimizing makespan for precedence-constrained scheduling is NP-hard in general. So one usually discusses:
>
> - exact exponential methods,
> - dynamic programming for small $n$,
> - or greedy and list-scheduling approximations.
>
> ## Standard greedy approach: list scheduling
>
> A common practical algorithm is:
>
> 1. Maintain the set of **available** tasks: tasks whose predecessors are all completed.
> 2. Whenever a computer becomes free, assign it an available task.
> 3. Repeat until all tasks are done.
>
> The main design choice is how to prioritize available tasks. A strong heuristic is to prioritize by **criticality**, e.g. the remaining longest-path length from that task to the end. Define
>
> $$
> h(v) = 1 + \max_{v \to w} h(w),
> $$
>
> with $h(v)=1$ if $v$ has no outgoing edges. Then, when multiple tasks are available, schedule the ones with largest $h(v)$ first. This tries to avoid delaying tasks on long dependency chains.
>
> ## Lower bounds for any schedule
>
> For unit-time tasks, any schedule length $T^*$ must satisfy two bounds. The work bound is $T^* \ge \lceil |V|/k \rceil$, since at most $k$ tasks can be processed per unit time. The critical-path bound is $T^* \ge L$, where $L$ is the length of the longest path. Combining these,
>
> $$
> T^* \ge \max\left( \left\lceil \frac{|V|}{k} \right\rceil, L \right).
> $$
>
> These bounds are useful both for reasoning about the problem and for evaluating heuristics.
>
> ## If the interviewer asks for an exact algorithm
>
> For small $n$, one can use dynamic programming over completed subsets. Let $S \subseteq V$ be the set of completed tasks. A task is available from state $S$ if all its predecessors lie in $S$. If up to $k$ available tasks can be run in one time step, define
>
> $$
> dp[S] = \text{minimum remaining time from completed set } S.
> $$
>
> Transition by choosing a subset $A$ of available tasks with $|A| \le k$, and set
>
> $$
> dp[S] = 1 + \min_{A} dp[S \cup A],
> $$
>
> with base case $dp[V] = 0$. This is exponential in $|V|$, roughly
>
> $$
> O(2^{|V|} \cdot \text{poly}(|V|)),
> $$
>
> so it is only suitable for small graphs.
>
> ## Summary
>
> Given a DAG of unit-time tasks and $k$ computers, three regimes apply.
>
> If $k=1$, any topological order works, and the makespan is $|V|$.
>
> If $k=\infty$, run every available task immediately; the makespan is the critical-path length, computable in $O(|V|+|E|)$ time.
>
> For general $k$, the problem is NP-hard. A standard practical solution is list scheduling: repeatedly schedule available tasks, usually prioritizing those with the largest remaining critical-path length. Any optimal schedule must be at least
>
> $$
> \max\left(\left\lceil \frac{|V|}{k} \right\rceil, L\right),
> $$
>
> where $L$ is the longest path length.
