> [!example] Question 760 · Citadel
> ## Software Engineering Intern Interview

Given an n x n chessboard, return the minimum number of knight moves required to get from point (a, b) to point (c, d).

[Source](https://www.thewallstreetquants.com/ebook#p=761)

> [!success]- Solution (Click to expand)
> ## Solution
>
> A knight move changes the position by one of the following vectors:
>
> $$
> (\pm 2, \pm 1), \qquad (\pm 1, \pm 2).
> $$
>
> We seek the minimum number of such moves needed to go from $(a,b)$ to $(c,d)$ on an $n \times n$ chessboard.
>
> ---
>
> ### 1. Model the board as a graph
>
> Interpret each square as a vertex in a graph.  
> Two vertices are connected by an edge if a knight can move from one square to the other in one move.
>
> Then the problem becomes:
>
> - start vertex: $(a,b)$
> - target vertex: $(c,d)$
> - find the length of the shortest path between them
>
> Since every move has equal cost, the appropriate method is **Breadth-First Search** (BFS).
>
> ---
>
> ### 2. BFS idea
>
> BFS explores positions in layers:
>
> - all squares reachable in $1$ move,
> - then all squares reachable in $2$ moves,
> - and so on.
>
> Therefore, the first time the target square $(c,d)$ is reached, the number of layers traversed is exactly the minimum number of knight moves.
>
> ---
>
> ### 3. Valid knight moves
>
> From a square $(x,y)$, the knight may move to any of:
>
> $$
> (x+2,y+1),\ (x+2,y-1),\ (x-2,y+1),\ (x-2,y-1),
> $$
>
> $$
> (x+1,y+2),\ (x+1,y-2),\ (x-1,y+2),\ (x-1,y-2).
> $$
>
> A move is valid only if the new square lies on the board:
>
> $$
> 0 \le x < n, \qquad 0 \le y < n
> $$
>
> (or equivalently $1 \le x \le n$, $1 \le y \le n$, depending on indexing convention).
>
> ---
>
> ### 4. Algorithm
>
> 1. If $(a,b) = (c,d)$, return $0$.
> 2. Create a queue for BFS.
> 3. Mark the starting square as visited and insert it into the queue with distance $0$.
> 4. Repeatedly:
>    - remove the front square $(x,y)$ with current distance $m$,
>    - generate all $8$ knight moves,
>    - for each valid unvisited square, mark it visited and enqueue it with distance $m+1$,
>    - if any generated square is $(c,d)$, return $m+1$.
> 5. If BFS finishes without reaching $(c,d)$, return $-1$.
>
> The value $-1$ is needed because on very small boards some squares may be unreachable.
>
> ---
>
> ### 5. Correctness
>
> BFS always explores vertices in nondecreasing order of distance from the start.
>
> Thus:
>
> - when a square is first visited, the number of moves used is the minimum possible,
> - so when $(c,d)$ is first reached, that distance is the minimum number of knight moves.
>
> Hence the algorithm is correct.
>
> ---
>
> ### 6. Complexity
>
> There are at most $n^2$ squares on the board, and each square has at most $8$ outgoing moves.
>
> Therefore:
>
> - **Time complexity:** $O(n^2)$
> - **Space complexity:** $O(n^2)$
>
> ---
>
> ### 7. Reference implementation
>
> ```python
> from collections import deque
>
> def min_knight_moves(n, a, b, c, d):
>     if (a, b) == (c, d):
>         return 0
>
>     moves = [
>         (2, 1), (2, -1), (-2, 1), (-2, -1),
>         (1, 2), (1, -2), (-1, 2), (-1, -2)
>     ]
>
>     visited = [[False] * n for _ in range(n)]
>     q = deque()
>     q.append((a, b, 0))
>     visited[a][b] = True
>
>     while q:
>         x, y, dist = q.popleft()
>
>         for dx, dy in moves:
>             nx, ny = x + dx, y + dy
>
>             if 0 <= nx < n and 0 <= ny < n and not visited[nx][ny]:
>                 if (nx, ny) == (c, d):
>                     return dist + 1
>                 visited[nx][ny] = True
>                 q.append((nx, ny, dist + 1))
>
>     return -1
> ```
>
> ---
>
> ### Final answer
>
> The minimum number of knight moves from $(a,b)$ to $(c,d)$ on an $n \times n$ board is obtained by performing a **Breadth-First Search** on the board graph, where each square connects to the $8$ possible knight moves. This runs in $O(n^2)$ time and returns the shortest number of moves.
