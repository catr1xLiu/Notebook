> [!example] Question 769 · Citadel
> ## Software Engineer Interview

Given an array representing heights of points on a mountain and a starting position, what is the highest point that is visible from that position?

[Source](https://www.thewallstreetquants.com/ebook#p=770)

> [!success]- Solution (Click to expand)
> ## Solution
>
> To determine the highest point visible from a given position on a mountain profile, model the mountain as an array of heights and use line-of-sight.
>
> Let the mountain be represented by heights
>
> $$
> h[0], h[1], \dots, h[n-1]
> $$
>
> and suppose the person stands at index $p$ with height $h[p]$.
>
> A point $i$ is visible from $p$ if the straight line segment joining $(p, h[p])$ and $(i, h[i])$ lies above or on every intermediate mountain point. In particular, a point that lies exactly on the line of sight (collinear with an earlier point) still counts as visible.
>
> ### Step 1: Compare slopes
>
> For a point to the right, $i > p$, define the slope
>
> $$
> m_i = \frac{h[i] - h[p]}{i - p}.
> $$
>
> Scanning to the right from $p+1$ to $n-1$, a point $i$ is visible exactly when its slope is at least every slope seen so far:
>
> $$
> m_i \ge \max_{p < j < i} m_j.
> $$
>
> The non-strict $\ge$ matters: if several consecutive points lie on the same line of sight, each one still has an unobstructed view, since the segment to it passes exactly through the earlier points rather than dipping below them.
>
> Similarly, for a point to the left, $i < p$, define the same slope. Scanning leftward from $p-1$ to $0$, a point is visible when its slope is at most every previously seen slope on that side, because the denominator is negative:
>
> $$
> m_i \le \min_{i < j < p} m_j.
> $$
>
> ### Step 2: Track the highest visible point
>
> Initialize the answer as the height at the current position:
>
> $$
> \text{best} = h[p].
> $$
>
> Then:
>
> - scan right, maintaining the maximum slope so far;
> - scan left, maintaining the minimum slope so far;
> - whenever a point is visible, including ties, update best to the larger of best and $h[i]$.
>
> ### Step 3: Algorithm
>
> ```text
> best = h[p]
>
> # scan right
> maxSlope = -infinity
> for i = p+1 to n-1:
>     slope = (h[i] - h[p]) / (i - p)
>     if slope >= maxSlope:
>         maxSlope = slope
>         best = max(best, h[i])
>
> # scan left
> minSlope = +infinity
> for i = p-1 down to 0:
>     slope = (h[i] - h[p]) / (i - p)
>     if slope <= minSlope:
>         minSlope = slope
>         best = max(best, h[i])
>
> return best
> ```
>
> Using $\ge$ and $\le$ instead of strict inequalities ensures that a run of collinear points is scanned through in full, so the farthest, and possibly highest, point on that line is captured rather than only the first.
>
> ### Step 4: Example with collinear points
>
> Consider $h = [1,3,5,7,9]$ with $p=0$, so $h[p]=1$. All four points to the right lie on a single line through $p$, since
>
> $$
> \frac{3-1}{1}=\frac{5-1}{2}=\frac{7-1}{3}=\frac{9-1}{4}=2.
> $$
>
> Scanning right with the $\ge$ rule, every one of these points ties the running maximum slope of $2$, so each is marked visible in turn, and best updates all the way to $h[4]=9$. A strict $>$ comparison would instead stop updating after the first point, incorrectly returning $3$, since every later point only ties rather than strictly exceeds that slope.
>
> ### Step 5: Complexity
>
> Each side is scanned once, so the running time is
>
> $$
> O(n)
> $$
>
> and the extra space is
>
> $$
> O(1).
> $$
>
> ## Final Answer
>
> The highest visible point is the maximum height among all points whose line of sight is not blocked by, and may run exactly along, any intermediate point. Using $\ge$ on the right scan and $\le$ on the left scan, rather than strict inequalities, correctly counts collinear points as visible. This can be found in $O(n)$ time by scanning left and right from the given position and keeping track of the extreme visible slope on each side.
