> [!example] Question 813 · Citadel
> ## Software Developer Intern Interview

If a Binary Search Tree was implemented incorrectly, such that a number to the left of a node is not smaller as it should be, how would you detect this mistake? What is the most efficient way to identify such an error?

[Source](https://www.thewallstreetquants.com/ebook#p=814)

> [!success]- Solution (Click to expand)
> To detect whether a binary search tree is written incorrectly, the goal is to verify the **BST property**:
>
> - every node in the left subtree must be **strictly smaller** than the node,
> - every node in the right subtree must be **strictly larger** than the node,
> - and this must hold for **every** node in the tree.
>
> ## Why a simple parent-child check is not enough
>
> Checking only whether a node’s left child is smaller and right child is larger is insufficient. A violation can occur deeper in a subtree.
>
> For example:
>
> - root $= 10$
> - left child $= 5$
> - right child of $5$ is $12$
>
> Here, $12 > 5$, so it looks valid relative to its parent, but since $12$ lies in the left subtree of $10$, it should also satisfy $12 < 10$. It does not, so the tree is invalid.
>
> ## Most efficient method
>
> The standard efficient approach is to traverse the tree while keeping track of the **allowed value range** for each node.
>
> ### Idea
>
> For each node:
>
> - it must lie between a lower bound and an upper bound,
> - for the left child, the upper bound becomes the current node’s value,
> - for the right child, the lower bound becomes the current node’s value.
>
> ### Algorithm
>
> If the current node has value $v$:
>
> - left subtree must contain only values in $(\text{min}, v)$,
> - right subtree must contain only values in $(v, \text{max})$.
>
> If any node violates its allowed range, the tree is not a BST.
>
> ## Pseudocode
>
> ```text
> isBST(node, min, max):
>     if node is null:
>         return true
>
>     if node.value <= min or node.value >= max:
>         return false
>
>     return isBST(node.left, min, node.value) 
>            and 
>            isBST(node.right, node.value, max)
> ```
>
> Initial call:
>
> ```text
> isBST(root, -∞, +∞)
> ```
>
> ## Example
>
> Consider:
>
> ```text
>         10
>        /  \
>       5    15
>        \
>         12
> ```
>
> Check:
>
> - $10$ must be in $(-\infty, \infty)$: valid
> - $5$ must be in $(-\infty, 10)$: valid
> - $12$ is in the left subtree of $10$, so it must be in $(5, 10)$
>
> But $12 \not< 10$, so the algorithm immediately detects the error.
>
> ## Time and space complexity
>
> Each node is visited once, so the time complexity is
>
> $$
> O(n)
> $$
>
> where $n$ is the number of nodes.
>
> The extra space is due to recursion depth:
>
> - worst case: $$O(n)$$ for a skewed tree,
> - balanced tree: $$O(\log n)$$
>
> ## Alternative method
>
> Another common method is to do an **in-order traversal**. For a valid BST, the visited values must appear in **strictly increasing order**. If at any point the current value is not greater than the previous one, the tree is invalid.
>
> This also runs in
>
> $$
> O(n)
> $$
>
> time.
>
> ## Conclusion
>
> The most efficient way to catch the mistake is to validate the tree in one traversal using **min/max bounds** for each node. This correctly detects all BST violations, including those that a local parent-child comparison would miss, and runs in
>
> $$
> O(n)
> $$
>
> time.
