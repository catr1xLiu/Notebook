> [!example] Question 1090 · IMC
> ## SWE Intern Interview

Can you perform binary search on a linked list? Explain why or why not.

[Source](https://www.thewallstreetquants.com/ebook#p=1091)

> [!success]- Solution (Click to expand)
> ## Solution
>
> Yes, binary search can be performed on a linked list, but it is generally **not efficient**.
>
> ### Reason
>
> Binary search relies on quickly accessing the middle element of the current search range. In an array, this is efficient because the middle index can be computed and accessed in $O(1)$ time.
>
> In a linked list, however, there is **no random access**. To reach the middle node, one must traverse from the head (or from the current left boundary), which takes linear time.
>
> ### Time complexity
>
> Suppose the linked list has $n$ elements.
>
> - Finding the middle of the list takes $O(n)$ time.
> - Then binary search reduces the search space by half.
> - The recurrence is therefore roughly
>   $$
>   T(n) = T\!\left(\frac{n}{2}\right) + O(n).
>   $$
>
> Solving this gives
> $$
> T(n) = O(n).
> $$
>
> Thus, binary search on a linked list does **not** achieve the usual $O(\log n)$ time of array-based binary search.
>
> ### Comparison
>
> - **Array**:
>   - Middle access: $O(1)$
>   - Binary search: $O(\log n)$
>
> - **Linked list**:
>   - Middle access: $O(n)$
>   - Binary search: $O(n)$ overall
>
> ### Conclusion
>
> Binary search is possible on a sorted linked list in principle, but because finding the middle node is costly, it offers no advantage over linear search in asymptotic time. Therefore, for linked lists, binary search is usually not preferred.
