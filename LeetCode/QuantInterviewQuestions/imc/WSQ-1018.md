> [!example] Question 1018 · IMC
> ## Software Engineer Interview

Does searching through a sorted binary search tree always have better time complexity than performing binary search on a sorted array?

[Source](https://www.thewallstreetquants.com/ebook#p=1019)

> [!success]- Solution (Click to expand)
> No.
>
> Binary search on a sorted array runs in worst-case time
>
> $$
> O(\log n).
> $$
>
> Searching in a binary search tree depends on the height $h$ of the tree, so its search time is
>
> $$
> O(h).
> $$
>
> There are two important cases:
>
> 1. **Balanced binary search tree**  
>    If the tree is balanced, then
>
>    $$
>    h = O(\log n),
>    $$
>
>    so search takes
>
>    $$
>    O(\log n).
>    $$
>
>    In this case, it is asymptotically the same as binary search, not better.
>
> 2. **Unbalanced binary search tree**  
>    If the tree becomes skewed, its height can be
>
>    $$
>    h = O(n),
>    $$
>
>    so search takes
>
>    $$
>    O(n),
>    $$
>
>    which is worse than binary search.
>
> Thus, searching in a binary search tree is **not always better** than binary search. At best, it matches binary search asymptotically when balanced; at worst, it is much worse.
>
> A useful practical distinction is this:
>
> - **Binary search on an array**: fast lookup, but insertions and deletions are typically $O(n)$.
> - **Balanced BST**: lookup, insertion, and deletion can all be $O(\log n)$.
>
> So if the question is only about **search**, then the answer is:
>
> $$
> \text{No, a binary search tree does not always have better search complexity than binary search.}
> $$
