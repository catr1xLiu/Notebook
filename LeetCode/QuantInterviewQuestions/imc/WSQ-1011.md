> [!example] Question 1011 · IMC
> ## Software Engineer Interview

Can an O(1) algorithm be made faster?

[Source](https://www.thewallstreetquants.com/ebook#p=1012)

> [!success]- Solution (Click to expand)
> Yes. Big-$O$ notation does not measure actual running time; it describes how running time grows as the input size $n$ increases.
>
> If an algorithm is $O(1)$, its running time is bounded by a constant:
> $$
> T(n) \le C
> $$
> for some constant $C$ and sufficiently large $n$.
>
> A different $O(1)$ algorithm may have a smaller constant. For example:
> $$
> T_1(n) = 1000, \qquad T_2(n) = 5.
> $$
> Both are $O(1)$, but the second is faster in practice.
>
> More generally, if
> $$
> T_1(n) = c_1, \qquad T_2(n) = c_2
> $$
> with $c_2 < c_1$, then both algorithms are $O(1)$, yet $T_2$ is faster.
>
> Thus, an $O(1)$ algorithm can certainly get faster by reducing constant factors, improving implementation, lowering memory overhead, using better hardware, or exploiting cache behavior. What cannot happen is improving its asymptotic class below constant time in the usual model, since $O(1)$ is already asymptotically optimal for any operation that must do at least some fixed amount of work.
>
> Therefore, the answer is: yes, an $O(1)$ algorithm can get faster in absolute terms, even though its asymptotic complexity remains $O(1)$.
