> [!example] Question 1065 · IMC
> ## Software Engineer Interview

What is the difference between threading and multiprocessing?

[Source](https://www.thewallstreetquants.com/ebook#p=1066)

> [!success]- Solution (Click to expand)
> ## Threading vs. Multiprocessing
>
> Both threading and multiprocessing are techniques for achieving concurrency, but they differ in how tasks are executed and how system resources are used.
>
> ### 1. Threading
>
> A **thread** is a smaller unit of execution within a single process. Multiple threads run inside the same process and therefore share the same memory space and resources.
>
> #### Characteristics
> - Threads share:
>   - memory
>   - variables
>   - file handles
>   - other process resources
> - Communication between threads is fast because they can access the same data directly.
> - Creating and switching between threads is usually less expensive than with processes.
> - Because memory is shared, threads require synchronization mechanisms such as:
>   - locks
>   - semaphores
>   - condition variables
>
> #### Advantages
> - Lower overhead
> - Fast communication
> - Useful for tasks involving waiting, such as:
>   - network requests
>   - user input
>   - file I/O
>
> #### Disadvantages
> - Shared memory can lead to:
>   - race conditions
>   - deadlocks
>   - data corruption
> - A crash in one thread can affect the entire process.
>
> ---
>
> ### 2. Multiprocessing
>
> A **process** is an independent program execution instance. In multiprocessing, multiple processes run separately, each with its own memory space.
>
> #### Characteristics
> - Each process has its own:
>   - address space
>   - variables
>   - resources
> - Processes do not share memory by default.
> - Communication between processes requires **inter-process communication** mechanisms, such as:
>   - pipes
>   - sockets
>   - queues
>   - shared memory tools
> - Creating and managing processes is more expensive than threads.
>
> #### Advantages
> - Better isolation: one process crashing usually does not crash others.
> - Can fully utilize multiple CPU cores for parallel computation.
> - Avoids many shared-memory synchronization problems.
>
> #### Disadvantages
> - Higher memory usage
> - More overhead in creating and communicating between processes
> - Data sharing is more complex
>
> ---
>
> ## Key Difference
>
> The main difference is:
>
> - **Threading** uses multiple execution paths within the **same process**, sharing memory.
> - **Multiprocessing** uses multiple **independent processes**, each with separate memory.
>
> ---
>
> ## When to Use Each
>
> - Use **threading** for **I/O-bound** tasks, where programs spend time waiting.
> - Use **multiprocessing** for **CPU-bound** tasks, where programs need true parallel execution across cores.
>
> ---
>
> ## Summary Table
>
> - **Feature Execution unit** — Threading: Threads within one process; Multiprocessing: Separate processes
> - **Feature Memory** — Threading: Shared; Multiprocessing: Separate
> - **Feature Communication** — Threading: Easy, direct; Multiprocessing: More expensive
> - **Feature Overhead** — Threading: Low; Multiprocessing: Higher
> - **Feature Safety** — Threading: Less isolated; Multiprocessing: More isolated
> - **Feature Best for** — Threading: I/O-bound tasks; Multiprocessing: CPU-bound tasks
>
> ## Final Answer
>
> Threading runs multiple threads inside one process with shared memory, making it lightweight and efficient for I/O-bound work. Multiprocessing runs multiple separate processes with independent memory, making it better for CPU-bound work and safer isolation, but with higher overhead.
