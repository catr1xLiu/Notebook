> [!example] Question 1009 · IMC
> ## Software Engineer Interview

Complete the function findValuation that returns the expected price of a house using linear interpolation, given arrays of historic house areas and prices. The function should round the result to the nearest integer. Function signature: findValuation(reqArea: int, area: list of int, price: list of int) -\> int, where reqArea is the area of the candidate house, area\[i\] is the area of the ith house sold, and price\[i\] is its price. Constraints: 500 \< reqArea \< 10^5, 500 \< area\[i\] \< 10^5 for all i.

[Source](https://www.thewallstreetquants.com/ebook#p=1010)

> ## Approach
>
> We are given the area and sale price of $n$ historic houses, and must estimate the price of a house with a requested area $\text{reqArea}$ by linear interpolation between the two known data points that bracket it.
>
> The steps are:
>
> - pair up each house as $(\text{area}[i], \text{price}[i])$ and sort the pairs by area
> - if several houses share the same area, replace them by a single point whose price is the average of their prices, so that each distinct area value appears once
> - locate the two consecutive distinct areas $x_0 \le x_1$ that bracket $\text{reqArea}$
> - if $\text{reqArea}$ falls before the first point or after the last point, extrapolate using the two nearest distinct points on that side, following the same linear formula
> - if $\text{reqArea}$ exactly matches a known area, return its (averaged) price directly
> - otherwise interpolate linearly between $(x_0,y_0)$ and $(x_1,y_1)$ using
>
> $$
> \text{price} = y_0 + (\text{reqArea}-x_0)\cdot\frac{y_1-y_0}{x_1-x_0}
> $$
>
> - round the result to the nearest integer before returning it
>
> ## Code
>
> ```python
> def findValuation(reqArea, area, price):
>     pts = sorted(zip(area, price))
>     n = len(pts)
>
>     merged = []
>     i = 0
>     while i < n:
>         j = i
>         total, count = 0, 0
>         while j < n and pts[j][0] == pts[i][0]:
>             total += pts[j][1]
>             count += 1
>             j += 1
>         merged.append((pts[i][0], total / count))
>         i = j
>
>     m = len(merged)
>     if m == 1:
>         return round(merged[0][1])
>
>     if reqArea <= merged[0][0]:
>         lo, hi = 0, 1
>     elif reqArea >= merged[-1][0]:
>         lo, hi = m - 2, m - 1
>     else:
>         lo = 0
>         while merged[lo + 1][0] < reqArea:
>             lo += 1
>         hi = lo + 1
>
>     x0, y0 = merged[lo]
>     x1, y1 = merged[hi]
>     if reqArea == x0:
>         return round(y0)
>     if reqArea == x1:
>         return round(y1)
>
>     est = y0 + (reqArea - x0) * (y1 - y0) / (x1 - x0)
>     return round(est)
> ```
>
> ## Notes
>
> - Averaging duplicate areas before interpolating avoids ambiguity about which price to anchor to when several historic houses share an area.
> - For requests outside the observed range, the code above extrapolates along the line through the two nearest distinct points; some versions of this problem instead specify clamping to the nearest endpoint price, in which case the bracket selection at the two ends is simply replaced by returning $y_0$ or $y_{m-1}$ directly. Either convention uses the same core interpolation logic in the interior.
> - Sorting dominates the cost, so the algorithm runs in $O(n\log n)$ time and $O(n)$ space.
