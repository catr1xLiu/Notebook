> ## 1) Minimum moves of a knight when bishop moves are also allowed
>
> ### Problem interpretation
>
> Assume a piece can move **either as a knight or as a bishop** in one move.  
> Given a chessboard position, the task is to find the minimum number of moves needed to go from a source square to a destination square.
>
> This is a shortest-path problem on an unweighted graph:
>
> - each square is a vertex,
> - an edge exists between two squares if one legal move of the hybrid piece connects them.
>
> Since every move has equal cost, the correct method is **Breadth-First Search**.
>
> ---
>
> ### Legal moves
>
> From a square $(x,y)$, the piece may move:
>
> #### Knight moves
> The $8$ knight displacements are
> $$
> (\pm 2,\pm 1), \quad (\pm 1,\pm 2).
> $$
>
> #### Bishop moves
> A bishop may move any positive distance along the $4$ diagonals:
> $$
> (x+k,y+k),\quad (x+k,y-k),\quad (x-k,y+k),\quad (x-k,y-k),
> $$
> for all integers $k \ge 1$ such that the square remains inside the board.
>
> ---
>
> ### Algorithm
>
> Use BFS starting from the source.
>
> For each dequeued square:
>
> 1. generate all $8$ knight moves;
> 2. generate all bishop-reachable squares along the $4$ diagonals;
> 3. if a generated square has not been visited, mark it visited, store distance $+1$, and enqueue it.
>
> The first time the destination is reached, the stored distance is the minimum number of moves.
>
> ---
>
> ### Correctness
>
> BFS explores vertices in nondecreasing order of distance from the source in an unweighted graph.  
> Here, every legal move corresponds to one edge, so:
>
> - all positions reached in $1$ move are processed before any in $2$ moves,
> - all positions reached in $2$ moves are processed before any in $3$ moves,
> - and so on.
>
> Therefore, the first time the destination square is visited, the associated number of moves is minimal.
>
> ---
>
> ### Complexity
>
> Let the board be $N \times N$.
>
> - There are $N^2$ squares.
> - For each square:
>   - knight transitions cost $O(1)$,
>   - bishop transitions may scan up to $O(N)$ squares.
>
> Hence the time complexity is
> $$
> O(N^3),
> $$
> and the space complexity is
> $$
> O(N^2).
> $$
>
> ---
>
> ### Reference implementation in Python
>
> ```python
> from collections import deque
>
> def min_moves_knight_with_bishop(n, start, target):
>     sx, sy = start
>     tx, ty = target
>
>     if start == target:
>         return 0
>
>     knight_dirs = [
>         (2, 1), (2, -1), (-2, 1), (-2, -1),
>         (1, 2), (1, -2), (-1, 2), (-1, -2)
>     ]
>
>     visited = [[False] * n for _ in range(n)]
>     dist = [[-1] * n for _ in range(n)]
>
>     q = deque()
>     q.append((sx, sy))
>     visited[sx][sy] = True
>     dist[sx][sy] = 0
>
>     while q:
>         x, y = q.popleft()
>         d = dist[x][y]
>
>         # Knight moves
>         for dx, dy in knight_dirs:
>             nx, ny = x + dx, y + dy
>             if 0 <= nx < n and 0 <= ny < n and not visited[nx][ny]:
>                 if (nx, ny) == (tx, ty):
>                     return d + 1
>                 visited[nx][ny] = True
>                 dist[nx][ny] = d + 1
>                 q.append((nx, ny))
>
>         # Bishop moves along 4 diagonals
>         for dx, dy in [(1, 1), (1, -1), (-1, 1), (-1, -1)]:
>             nx, ny = x + dx, y + dy
>             while 0 <= nx < n and 0 <= ny < n:
>                 if not visited[nx][ny]:
>                     if (nx, ny) == (tx, ty):
>                         return d + 1
>                     visited[nx][ny] = True
>                     dist[nx][ny] = d + 1
>                     q.append((nx, ny))
>                 nx += dx
>                 ny += dy
>
>     return -1
> ```

> ## 2) Implement a stack supporting `push`, `pop`, `peek`, `sum`, and `inc`
>
> ### Problem interpretation
>
> Design a stack that supports the usual operations:
>
> - `push(x)`
> - `pop()`
> - `peek()`
>
> and also:
>
> - `sum()` = return the sum of all current elements,
> - `inc(k, val)` = increment the bottom $k$ elements by `val`.
>
> The goal is to support these efficiently.
>
> ---
>
> ### Key idea
>
> Maintain:
>
> 1. a normal array `stack`,
> 2. a running total `total`,
> 3. a lazy increment array `inc`.
>
> The array `inc[i]` stores an increment that should be applied to all elements from the bottom up to index $i$, but is postponed until needed.
>
> This allows `inc(k, val)` to be done in $O(1)$ time:
>
> - let $i = \min(k, \text{size}) - 1$,
> - add `val` to `inc[i]`.
>
> When popping index $i$:
>
> - the actual value is `stack[i] + inc[i]`,
> - before removing it, propagate `inc[i]` downward to `inc[i-1]`.
>
> This is the standard lazy-propagation trick.
>
> ---
>
> ### Operations
>
> #### `push(x)`
> - append $x$ to the stack,
> - append $0$ to `inc`,
> - update `total += x`.
>
> #### `pop()`
> If empty, return an error value.
>
> Otherwise let top index be $i$.
>
> - actual popped value:
>   $$
>   \text{val} = \text{stack}[i] + \text{inc}[i]
>   $$
> - if $i > 0$, propagate:
>   $$
>   \text{inc}[i-1] \mathrel{+}= \text{inc}[i]
>   $$
> - remove top entries,
> - update
>   $$
>   \text{total} \mathrel{-}= \text{val}
>   $$
>
> #### `peek()`
> Top actual value is
> $$
> \text{stack}[-1] + \text{inc}[-1].
> $$
>
> #### `sum()`
> Return `total`.
>
> #### `inc(k, val)`
> Let
> $$
> i = \min(k, \text{size}) - 1.
> $$
> If $i \ge 0$:
>
> - store the lazy increment:
>   $$
>   \text{inc}[i] \mathrel{+}= \text{val}
>   $$
> - since bottom $\min(k,\text{size})$ elements increase by `val`, increase total by
>   $$
>   \min(k,\text{size}) \cdot \text{val}.
>   $$
>
> Thus `sum()` remains $O(1)$.
>
> ---
>
> ### Complexity
>
> Each operation runs in $O(1)$ time:
>
> - `push`: $O(1)$
> - `pop`: $O(1)$
> - `peek`: $O(1)$
> - `sum`: $O(1)$
> - `inc`: $O(1)$
>
> Space usage is
> $$
> O(n),
> $$
> where $n$ is the current stack size.
>
> ---
>
> ### Reference implementation in Python
>
> ```python
> class CustomStack:
>     def __init__(self):
>         self.stack = []
>         self.inc_arr = []
>         self.total = 0
>
>     def push(self, x):
>         self.stack.append(x)
>         self.inc_arr.append(0)
>         self.total += x
>
>     def pop(self):
>         if not self.stack:
>             return None
>
>         i = len(self.stack) - 1
>         val = self.stack[i] + self.inc_arr[i]
>
>         if i > 0:
>             self.inc_arr[i - 1] += self.inc_arr[i]
>
>         self.stack.pop()
>         self.inc_arr.pop()
>         self.total -= val
>         return val
>
>     def peek(self):
>         if not self.stack:
>             return None
>         i = len(self.stack) - 1
>         return self.stack[i] + self.inc_arr[i]
>
>     def sum(self):
>         return self.total
>
>     def inc(self, k, val):
>         cnt = min(k, len(self.stack))
>         if cnt <= 0:
>             return
>         self.inc_arr[cnt - 1] += val
>         self.total += cnt * val
> ```
>
> ---
>
> ### Example
>
> Suppose the stack evolves as follows.
>
> 1. `push(3)`  
>    stack: $[3]$, sum $= 3$
>
> 2. `push(5)`  
>    stack: $[3,5]$, sum $= 8$
>
> 3. `inc(2,4)`  
>    logical stack becomes $[7,9]$, sum $= 16$
>
> 4. `peek()` returns $9$
>
> 5. `pop()` returns $9$  
>    remaining logical stack: $[7]$, sum $= 7$
>
> 6. `pop()` returns $7$
>
> This matches the intended behavior.
>
> ---
>
> ## Final answers
>
> 1. For minimum moves when both knight and bishop moves are allowed, model the board as an unweighted graph and use **BFS**. This yields the minimum number of moves in
> $$
> O(N^3)
> $$
> time on an $N \times N$ board.
>
> 2. For a stack supporting `push`, `pop`, `peek`, `sum`, and `inc`, use:
>    - a main stack,
>    - a lazy increment array,
>    - a running total.  
>
>    Then every operation can be implemented in
> $$
> O(1)
> $$
> time.
