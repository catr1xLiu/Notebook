> ## 1) Minimum moves of a Knight when you also have a Bishop
>
> ### Approach
>
> Treat the board as an unweighted graph.
>
> - Each square is a node.
> - From any square, you may move either:
>   - as a knight, to any of the up to $8$ knight-reachable squares, or
>   - as a bishop, along any diagonal to any square reachable in one bishop move.
>
> Since every move has equal cost $1$, the minimum number of moves is found by **breadth-first search**.
>
> ### Graph construction
>
> For a square $(r,c)$ on an $N \times N$ board:
>
> #### Knight moves
> The knight can move to:
> $$
> (r \pm 2, c \pm 1), \quad (r \pm 1, c \pm 2)
> $$
> subject to staying within board bounds.
>
> #### Bishop moves
> The bishop can move along the four diagonals:
> $$
> (r+i, c+i), \quad (r+i, c-i), \quad (r-i, c+i), \quad (r-i, c-i)
> $$
> for all integers $i \ge 1$ such that the destination remains on the board.
>
> ### BFS algorithm
>
> Let the source be $s$ and the target be $t$.
>
> 1. Initialize a queue with $s$.
> 2. Maintain an array $\mathrm{dist}$, initially $-1$ everywhere.
> 3. Set $\mathrm{dist}[s] = 0$.
> 4. While the queue is not empty:
>    - remove the front square $u$,
>    - generate all legal knight and bishop moves from $u$,
>    - for each unvisited neighbor $v$, set
>      $$
>      \mathrm{dist}[v] = \mathrm{dist}[u] + 1
>      $$
>      and push $v$ into the queue.
> 5. When $t$ is reached, $\mathrm{dist}[t]$ is the minimum number of moves.
>
> ### Correctness
>
> BFS explores positions in nondecreasing order of number of moves from the source. Since each legal move—knight or bishop—costs exactly $1$, the first time the target is visited gives the shortest path length. Hence the algorithm returns the minimum number of moves.
>
> ### Complexity
>
> There are $N^2$ squares.
>
> - Each square has at most $8$ knight neighbors.
> - Each square has $O(N)$ bishop neighbors.
>
> Thus the total running time is:
> $$
> O(N^3)
> $$
> in the straightforward implementation, and the space usage is:
> $$
> O(N^2)
> $$
>
> ### Reference implementation
>
> ```python
> from collections import deque
>
> def min_moves_knight_with_bishop(n, start, target):
>     sr, sc = start
>     tr, tc = target
>     
>     if start == target:
>         return 0
>     
>     dist = [[-1] * n for _ in range(n)]
>     q = deque()
>     q.append((sr, sc))
>     dist[sr][sc] = 0
>
>     knight_dirs = [
>         (2, 1), (2, -1), (-2, 1), (-2, -1),
>         (1, 2), (1, -2), (-1, 2), (-1, -2)
>     ]
>
>     while q:
>         r, c = q.popleft()
>         d = dist[r][c]
>
>         # Knight moves
>         for dr, dc in knight_dirs:
>             nr, nc = r + dr, c + dc
>             if 0 <= nr < n and 0 <= nc < n and dist[nr][nc] == -1:
>                 if (nr, nc) == target:
>                     return d + 1
>                 dist[nr][nc] = d + 1
>                 q.append((nr, nc))
>
>         # Bishop moves
>         for dr, dc in [(1,1), (1,-1), (-1,1), (-1,-1)]:
>             nr, nc = r + dr, c + dc
>             while 0 <= nr < n and 0 <= nc < n:
>                 if dist[nr][nc] == -1:
>                     if (nr, nc) == target:
>                         return d + 1
>                     dist[nr][nc] = d + 1
>                     q.append((nr, nc))
>                 nr += dr
>                 nc += dc
>
>     return -1
> ```

> ## 2) Stack supporting `push`, `pop`, `peek`, `sum`, and `inc`
>
> ### Goal
>
> Design a stack that supports:
>
> - `push(x)`: push $x$ onto the stack,
> - `pop()`: remove and return the top element,
> - `peek()`: return the top element without removing it,
> - `sum()`: return the sum of all elements in the stack,
> - `inc(k, val)`: increment the bottom $k$ elements by $val$,
>
> with efficient time complexity.
>
> ### Key idea
>
> To support `sum()` efficiently, maintain a running total.
>
> To support `inc(k, val)` efficiently, do **lazy propagation**:
>
> - Let `inc[i]` store a pending increment that should apply to all elements from the bottom up to index $i$.
> - When popping from index $i$, apply its accumulated increment to that element.
> - Before removing it, pass its pending increment downward to index $i-1$.
>
> This makes `inc(k, val)` run in $O(1)$ time.
>
> ### Data structure
>
> Maintain:
>
> - `stack`: actual pushed values,
> - `lazy`: same length as `stack`, where `lazy[i]` stores pending increment affecting index $i$ and below,
> - `total`: sum of the current stack values after all increments.
>
> ### Operations
>
> #### `push(x)`
> Append $x$ to `stack`, append $0$ to `lazy`, and update:
> $$
> \mathrm{total} \leftarrow \mathrm{total} + x
> $$
>
> #### `pop()`
> Suppose the top is at index $i$.
>
> - The actual popped value is:
>   $$
>   \text{stack}[i] + \text{lazy}[i]
>   $$
> - If $i > 0$, propagate:
>   $$
>   \text{lazy}[i-1] \leftarrow \text{lazy}[i-1] + \text{lazy}[i]
>   $$
> - Subtract the popped value from `total`.
>
> #### `peek()`
> If the top is at index $i$, return:
> $$
> \text{stack}[i] + \text{lazy}[i]
> $$
>
> #### `sum()`
> Return `total`.
>
> #### `inc(k, val)`
> Let
> $$
> i = \min(k, \text{size}) - 1
> $$
> If $i \ge 0$, then:
>
> - add $val$ lazily:
>   $$
>   \text{lazy}[i] \leftarrow \text{lazy}[i] + val
>   $$
> - update total because exactly $\min(k, \text{size})$ elements increase by $val$:
>   $$
>   \mathrm{total} \leftarrow \mathrm{total} + \min(k, \text{size}) \cdot val
>   $$
>
> ### Complexity
>
> Each operation runs in:
> $$
> O(1)
> $$
> time.
>
> Space usage is:
> $$
> O(n)
> $$
> for a stack of size $n$.
>
> ### Reference implementation
>
> ```python
> class CustomStack:
>     def __init__(self):
>         self.stack = []
>         self.lazy = []
>         self.total = 0
>
>     def push(self, x):
>         self.stack.append(x)
>         self.lazy.append(0)
>         self.total += x
>
>     def pop(self):
>         if not self.stack:
>             return None
>
>         i = len(self.stack) - 1
>         inc_val = self.lazy[i]
>         val = self.stack[i] + inc_val
>
>         self.stack.pop()
>         self.lazy.pop()
>
>         if i > 0:
>             self.lazy[i - 1] += inc_val
>
>         self.total -= val
>         return val
>
>     def peek(self):
>         if not self.stack:
>             return None
>         i = len(self.stack) - 1
>         return self.stack[i] + self.lazy[i]
>
>     def sum(self):
>         return self.total
>
>     def inc(self, k, val):
>         m = min(k, len(self.stack))
>         if m <= 0:
>             return
>         self.lazy[m - 1] += val
>         self.total += m * val
> ```
>
> ### Example
>
> Starting with an empty stack:
>
> 1. `push(4)`  
>    Stack: $[4]$, sum $= 4$
>
> 2. `push(7)`  
>    Stack: $[4,7]$, sum $= 11$
>
> 3. `inc(2, 3)`  
>    Bottom $2$ elements become $[7,10]$, sum $= 17$
>
> 4. `peek()` returns $10$
>
> 5. `pop()` returns $10$
>
> 6. Remaining stack is $[7]$, and `sum()` returns $7$
>
> ## Final answers
>
> 1. Use **BFS** on the board graph where edges correspond to all legal knight moves and all legal bishop moves. This yields the minimum number of moves in $O(N^3)$ time and $O(N^2)$ space.
>
> 2. Implement the stack using:
>    - an array for values,
>    - a parallel lazy-increment array,
>    - a running total for `sum()`.  
>    Then `push`, `pop`, `peek`, `sum`, and `inc` all run in $O(1)$ time.
