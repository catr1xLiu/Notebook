> ## Software Engineer Interview

What is the time complexity of different std::set operations?

> ## Complexity of different std::set operations
>
> In C++, `std::set` is typically implemented as a balanced binary search tree, commonly a red-black tree. Because the tree remains balanced, most search-related operations take logarithmic time.
>
> Let $n$ be the number of elements in the set.
>
> ### Core operations
>
> - `insert(x)` : $O(\log n)$
> - `erase(x)` : $O(\log n)$
> - `find(x)` : $O(\log n)$
> - `count(x)` : $O(\log n)$
>
> Since `std::set` contains unique keys, `count(x)` is either $0$ or $1$, but locating the key still takes $O(\log n)$.
>
> ### Boundary and range queries
>
> - `lower_bound(x)` : $O(\log n)$
> - `upper_bound(x)` : $O(\log n)$
> - `equal_range(x)` : $O(\log n)$
>
> For `std::set`, `equal_range(x)` gives the range where $x$ would appear; because keys are unique, that range has size at most $1$.
>
> ### Iterators
>
> - `begin()` : $O(1)$
> - `end()` : $O(1)$
> - Increment/decrement iterator, such as `++it` or `--it` : amortized $O(1)$
>
> ### Size and emptiness
>
> - `size()` : $O(1)$
> - `empty()` : $O(1)$
>
> ### Erasing by iterator or range
>
> - `erase(it)` : amortized $O(1)$ for the iterator position itself once located; interview-wise, it is safest to describe overall single-element deletion as $O(\log n)$
> - `erase(first, last)` : proportional to the number of elements erased plus rebalancing cost, commonly stated as $O(k\log n)$ where $k$ is the number of erased elements
>
> ### Construction
>
> - Constructing from a range of $n$ elements: typically $O(n \log n)$
> - Copying a set of size $n$: $O(n)$
>
> ### Access by index
>
> `std::set` does **not** support random access. There is no $O(1)$ indexing like with a vector. Reaching the $k$-th element requires iterator advancement, which is $O(k)$.
>
> ### Summary
>
> - Operation `insert` — Complexity: $O(\log n)$
> - Operation `erase(key)` — Complexity: $O(\log n)$
> - Operation `find` — Complexity: $O(\log n)$
> - Operation `count` — Complexity: $O(\log n)$
> - Operation `lower_bound` — Complexity: $O(\log n)$
> - Operation `upper_bound` — Complexity: $O(\log n)$
> - Operation `equal_range` — Complexity: $O(\log n)$
> - Operation `begin`, `end` — Complexity: $O(1)$
> - Operation `size`, `empty` — Complexity: $O(1)$
> - Operation iterator `++`, `--` — Complexity: amortized $O(1)$
>
> For interviews, the key takeaway is: because `std::set` is a balanced BST, lookup, insertion, and deletion are generally $O(\log n)$.
