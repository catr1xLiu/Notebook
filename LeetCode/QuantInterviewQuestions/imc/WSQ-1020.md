> [!example] Question 1020 · IMC
> ## Software Engineer Interview

How would you implement a trade matching engine? The API should support: 1) adding Buy/Sell orders, which should return a Trade if an existing order matches the new one; 2) deleting pending orders; 3) getting market depth or demand, i.e., the range of buy/sell prices and total volume of pending orders at each price.

> # Trade Matching Engine
>
> A suitable implementation is an **order book** with two sides:
>
> - **Buy side (bids)**: highest price has priority.
> - **Sell side (asks)**: lowest price has priority.
>
> Within the same price, orders are matched in **FIFO** order.  
> This gives the standard **price-time priority** used by exchanges.
>
> ---
>
> ## 1. Requirements and Matching Rules
>
> Each order has at least:
>
> - $id$
> - $side \in \{\text{Buy}, \text{Sell}\}$
> - $price$
> - $quantity$
> - $timestamp$
>
> A new order is processed as follows.
>
> - A **buy** order matches the best available sell orders with price $\le$ its price.
> - A **sell** order matches the best available buy orders with price $\ge$ its price.
> - Matching continues until:
>   - the incoming order is fully filled, or
>   - no compatible resting order remains.
>
> If the incoming order is not fully filled, the remainder becomes a pending order in the book.
>
> Deletion removes a still-pending order by $id$.
>
> Market depth returns, for each side, the total resting volume at each price level.
>
> ---
>
> ## 2. Core Data Structures
>
> To support efficient matching, deletion, and depth queries, use:
>
> ## 2.1 Price Levels
>
> For each side, maintain a mapping
>
> $$
> \text{price} \mapsto \text{queue of orders at that price}
> $$
>
> Since FIFO is required, each price level should store orders in insertion order, for example:
>
> - doubly linked list, or
> - queue with removable nodes.
>
> Each price level also stores:
>
> - total quantity at that price.
>
> ## 2.2 Sorted Price Index
>
> We must quickly find:
>
> - highest bid price,
> - lowest ask price.
>
> Thus maintain:
>
> - bids in a structure sorted in descending price,
> - asks in a structure sorted in ascending price.
>
> A balanced binary search tree is appropriate:
>
> - Java: `TreeMap`
> - C++: `map`
> - Python: use a sorted structure such as `sortedcontainers.SortedDict`, or implement a tree/heap combination.
>
> ## 2.3 Order Lookup by ID
>
> To support deletion in $O(1)$ or close to it, maintain
>
> $$
> id \mapsto \text{order record}
> $$
>
> The order record should include:
>
> - side,
> - current remaining quantity,
> - price level reference,
> - node reference inside the queue/list.
>
> This allows direct removal without scanning.
>
> ---
>
> ## 3. Object Model
>
> A clean model is:
>
> ```text
> Order
>   id
>   side
>   price
>   remainingQty
>   timestamp
>
> Trade
>   buyOrderId
>   sellOrderId
>   price
>   quantity
>
> PriceLevel
>   price
>   totalQty
>   orders (FIFO)
>
> OrderBook
>   bids: sorted price -> PriceLevel
>   asks: sorted price -> PriceLevel
>   orderIndex: id -> OrderHandle
> ```
>
> If one API call may produce several fills, then either:
>
> - return a list of `Trade`, or
> - return only the first trade and keep filling internally.
>
> In practice, a list is more correct, since one order can match multiple resting orders.
>
> ---
>
> ## 4. API Design
>
> A reasonable API is:
>
> ```java
> List<Trade> addBuyOrder(String id, long price, long qty)
> List<Trade> addSellOrder(String id, long price, long qty)
> boolean deleteOrder(String id)
> MarketDepth getDepth()
> ```
>
> where `MarketDepth` might be:
>
> ```java
> class MarketDepth {
>     List<DepthLevel> bids; // sorted high to low
>     List<DepthLevel> asks; // sorted low to high
> }
>
> class DepthLevel {
>     long price;
>     long totalQty;
> }
> ```
>
> If the specification insists that add methods return a single `Trade`, then they should return:
>
> - the first trade, or
> - `null` if no trade occurred.
>
> However, matching engines usually return **all resulting trades**.
>
> ---
>
> ## 5. Matching Algorithm
>
> ## 5.1 Add Buy Order
>
> Suppose a buy order $(id, p, q)$ arrives.
>
> While:
>
> - $q > 0$, and
> - the best ask exists, and
> - $\text{bestAskPrice} \le p$,
>
> do:
>
> 1. Take the oldest order from the best ask level.
> 2. Let the resting sell order have remaining quantity $r$.
> 3. Execute
>
> $$
> m = \min(q, r)
> $$
>
> 4. Create trade:
>
>    - buyer: incoming buy order
>    - seller: resting sell order
>    - quantity: $m$
>    - price: resting order price
>
> 5. Decrease both quantities by $m$.
> 6. If the resting order becomes zero:
>    - remove it from the queue,
>    - remove it from `orderIndex`.
> 7. If the price level becomes empty:
>    - remove the price level from the ask tree.
>
> After the loop, if $q > 0$, insert the remainder as a resting bid at price $p$.
>
> ## 5.2 Add Sell Order
>
> This is symmetric.
>
> While:
>
> - $q > 0$, and
> - the best bid exists, and
> - $\text{bestBidPrice} \ge p$,
>
> match against the oldest order at the best bid level.
>
> ---
>
> ## 6. Deletion Algorithm
>
> To delete an order by $id$:
>
> 1. Look up the order in `orderIndex`.
> 2. If absent, return `false`.
> 3. Remove its node from the corresponding price level queue.
> 4. Subtract its remaining quantity from that level’s total.
> 5. If the price level becomes empty, remove that price from the tree.
> 6. Remove the order from `orderIndex`.
> 7. Return `true`.
>
> Because the node is directly referenced, no scan is needed.
>
> ---
>
> ## 7. Market Depth
>
> To produce market depth:
>
> - Traverse bid price levels from highest to lowest.
> - Traverse ask price levels from lowest to highest.
> - For each level, output:
>
> $$
> (\text{price}, \text{total resting quantity})
> $$
>
> This is naturally supported by the sorted maps.
>
> If only a price range is requested, use tree-range queries.
>
> For example:
>
> - bids between $[p_1, p_2]$
> - asks between $[p_3, p_4]$
>
> Balanced trees support this efficiently.
>
> ---
>
> ## 8. Time Complexity
>
> Assume balanced trees and direct node references.
>
> Let $L$ be the number of price levels touched during matching.
>
> ### Add order
> - Finding best price: $O(1)$ or $O(\log n)$ depending on structure.
> - Matching across $L$ levels/orders: $O(L \log n)$ in the worst case if tree updates occur.
> - Insertion of leftover: $O(\log n)$.
>
> Typically:
>
> $$
> O((k+1)\log n)
> $$
>
> where $k$ is the number of matched resting orders.
>
> ### Delete order
> - Lookup by id: $O(1)$
> - Remove from level and possibly tree: $O(1)$ plus $O(\log n)$ if deleting an empty price level
>
> So:
>
> $$
> O(\log n)
> $$
>
> ### Get depth
> If returning all levels:
>
> $$
> O(m)
> $$
>
> where $m$ is the number of nonempty price levels.
>
> ---

> ## 9. Pseudocode
>
> ## 9.1 Add Buy
>
> ```java
> List<Trade> addBuyOrder(String id, long price, long qty) {
>     List<Trade> trades = new ArrayList<>();
>
>     while (qty > 0 && !asks.isEmpty()) {
>         PriceLevel bestAsk = asks.firstEntry().getValue();
>         if (bestAsk.price > price) break;
>
>         Order resting = bestAsk.peekFirst();
>         long matched = Math.min(qty, resting.remainingQty);
>
>         trades.add(new Trade(id, resting.id, bestAsk.price, matched));
>
>         qty -= matched;
>         resting.remainingQty -= matched;
>         bestAsk.totalQty -= matched;
>
>         if (resting.remainingQty == 0) {
>             bestAsk.removeFirst();
>             orderIndex.remove(resting.id);
>         }
>
>         if (bestAsk.isEmpty()) {
>             asks.remove(bestAsk.price);
>         }
>     }
>
>     if (qty > 0) {
>         Order order = new Order(id, BUY, price, qty, now());
>         PriceLevel level = bids.get(price);
>         if (level == null) {
>             level = new PriceLevel(price);
>             bids.put(price, level);
>         }
>         Node node = level.append(order);
>         level.totalQty += qty;
>         orderIndex.put(id, new OrderHandle(order, level, node));
>     }
>
>     return trades;
> }
> ```
>
> ## 9.2 Add Sell
>
> ```java
> List<Trade> addSellOrder(String id, long price, long qty) {
>     List<Trade> trades = new ArrayList<>();
>
>     while (qty > 0 && !bids.isEmpty()) {
>         PriceLevel bestBid = bids.firstEntry().getValue(); // descending map
>         if (bestBid.price < price) break;
>
>         Order resting = bestBid.peekFirst();
>         long matched = Math.min(qty, resting.remainingQty);
>
>         trades.add(new Trade(resting.id, id, bestBid.price, matched));
>
>         qty -= matched;
>         resting.remainingQty -= matched;
>         bestBid.totalQty -= matched;
>
>         if (resting.remainingQty == 0) {
>             bestBid.removeFirst();
>             orderIndex.remove(resting.id);
>         }
>
>         if (bestBid.isEmpty()) {
>             bids.remove(bestBid.price);
>         }
>     }
>
>     if (qty > 0) {
>         Order order = new Order(id, SELL, price, qty, now());
>         PriceLevel level = asks.get(price);
>         if (level == null) {
>             level = new PriceLevel(price);
>             asks.put(price, level);
>         }
>         Node node = level.append(order);
>         level.totalQty += qty;
>         orderIndex.put(id, new OrderHandle(order, level, node));
>     }
>
>     return trades;
> }
> ```
>
> ## 9.3 Delete
>
> ```java
> boolean deleteOrder(String id) {
>     OrderHandle h = orderIndex.get(id);
>     if (h == null) return false;
>
>     h.level.remove(h.node);
>     h.level.totalQty -= h.order.remainingQty;
>
>     if (h.level.isEmpty()) {
>         if (h.order.side == BUY) {
>             bids.remove(h.level.price);
>         } else {
>             asks.remove(h.level.price);
>         }
>     }
>
>     orderIndex.remove(id);
>     return true;
> }
> ```
>
> ## 9.4 Depth
>
> ```java
> MarketDepth getDepth() {
>     MarketDepth depth = new MarketDepth();
>
>     for (PriceLevel level : bids.values()) {
>         depth.bids.add(new DepthLevel(level.price, level.totalQty));
>     }
>
>     for (PriceLevel level : asks.values()) {
>         depth.asks.add(new DepthLevel(level.price, level.totalQty));
>     }
>
>     return depth;
> }
> ```

> ## 10. Important Design Choices
>
> ## 10.1 Trade Price
> A trade is usually executed at the **resting order’s price**.  
> This preserves price-time priority and is standard practice.
>
> ## 10.2 Partial Fills
> Orders may be partially filled; therefore each order must track:
>
> $$
> \text{remainingQty}
> $$
>
> rather than only original quantity.
>
> ## 10.3 FIFO at Each Price
> If two orders have the same price, the earlier one must be matched first. Hence a queue or linked list per price level is necessary.
>
> ## 10.4 Delete Only Pending Orders
> Filled or already deleted orders should not be deletable. This is naturally enforced by removing them from `orderIndex`.
>
> ## 10.5 Concurrency
> If the engine is used in a multithreaded environment, updates to the order book must be serialized. In practice:
>
> - use a single-threaded matching loop, or
> - protect all book mutations with a lock.
>
> A real exchange engine often uses a single-threaded event processor for determinism and simplicity.
>
> ---
>
> ## 11. Final Design Summary
>
> Implement the engine as an order book with:
>
> - a descending sorted map of bid price levels,
> - an ascending sorted map of ask price levels,
> - a FIFO queue of orders within each price level,
> - a hash map from order id to its location in the book.
>
> This supports:
>
> - **adding orders** with correct price-time matching,
> - **deleting pending orders** efficiently,
> - **getting market depth** by aggregating quantity at each price level.
>
> The key operations have efficient complexity:
>
> - add/match: $O((k+1)\log n)$
> - delete: $O(\log n)$
> - full depth snapshot: $O(m)$
>
> where $k$ is the number of matched orders, $n$ the number of price levels, and $m$ the number of nonempty levels.
