> [!example] Question 1076 · IMC
> ## Software Engineer Interview

What is the Big O notation for common operations performed on a heap? What about operations on a hashmap?

[Source](https://www.thewallstreetquants.com/ebook#p=1077)

> [!success]- Solution (Click to expand)
> ## Heap
>
> Assume a binary heap implemented as an array.
>
> - **Find min / max**:  
>   The root stores the extreme element, so this is  
>   $$O(1).$$
>
> - **Insert**:  
>   Insert at the end, then restore heap order by bubbling up through the height of the tree. Since a binary heap has height  
>   $$O(\log n),$$  
>   insertion is  
>   $$O(\log n).$$
>
> - **Extract min / max**:  
>   Remove the root, move the last element to the root, then bubble down. This also takes  
>   $$O(\log n).$$
>
> - **Decrease-key / increase-key**:  
>   Restore heap order by moving an element up or down the tree, so  
>   $$O(\log n).$$
>
> - **Build heap** from an unsorted array:  
>   Using the standard bottom-up heapify algorithm, this is  
>   $$O(n).$$
>
> - **Search for an arbitrary element**:  
>   A heap is not ordered enough for binary search, so in general this is  
>   $$O(n).$$
>
> Summary for a heap:
>
> - peek root: $$O(1)$$
> - insert: $$O(\log n)$$
> - extract root: $$O(\log n)$$
> - build heap: $$O(n)$$
> - arbitrary search: $$O(n)$$
>
> ---
>
> ## Hash map
>
> Assume a hash table with a good hash function and resizing.
>
> ### Average-case / expected time
>
> - **Lookup**:  
>   $$O(1)$$
>
> - **Insert**:  
>   $$O(1)$$
>
> - **Delete**:  
>   $$O(1)$$
>
> These are constant time on average because keys are distributed across buckets and the load factor is controlled.
>
> ### Worst-case time
>
> If many keys collide into the same bucket, operations may degrade to
>
> - **Lookup**: $$O(n)$$
> - **Insert**: $$O(n)$$
> - **Delete**: $$O(n)$$
>
> ### Resizing
>
> When the table resizes, one resize step may cost
>
> $$O(n),$$
>
> but since resizing happens only occasionally, the **amortized** cost of insertion remains
>
> $$O(1).$$
>
> Summary for a hash map:
>
> - lookup: average $$O(1)$$, worst-case $$O(n)$$
> - insert: average/amortized $$O(1)$$, worst-case $$O(n)$$
> - delete: average $$O(1)$$, worst-case $$O(n)$$
>
> ---
>
> ## Final comparison
>
> - A **heap** is good for repeatedly accessing and removing the minimum or maximum:
>   - root access: $$O(1)$$
>   - insert/remove root: $$O(\log n)$$
>
> - A **hash map** is good for key-based access:
>   - lookup/insert/delete: average $$O(1)$$
>   - but no ordering guarantees, and worst-case can be $$O(n)$$.
