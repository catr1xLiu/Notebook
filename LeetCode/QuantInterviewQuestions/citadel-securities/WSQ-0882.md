> [!example] Question 882 · Citadel Securities
> ## Software Engineer New Grad Interview

Implement a service to maximize throughput by increasing the number of processes, given a fixed budget constraint.

[Source](https://www.thewallstreetquants.com/ebook#p=883)

> [!success]- Solution (Click to expand)
> ## Solution
>
> This is the classic **maximize throughput under a budget** problem: each service has a current number of processes, a scaling cost per added process, and a throughput that equals the minimum across services of
>
> $$
> \left\lfloor \frac{\text{processes}_i}{\text{throughput}_i} \right\rfloor .
> $$
>
> The goal is to spend at most the given budget to maximize the common throughput.
>
> The key observation is that the answer can be found with **binary search** on the target throughput.
>
> ---
>
> ## Approach
>
> Suppose we want to check whether a target throughput $x$ is achievable.
>
> For service $i$:
>
> - current processes: $p_i$
> - cost per extra process: $c_i$
> - throughput factor: $t_i$
>
> To support throughput $x$, service $i$ must have at least
>
> $$
> x \cdot t_i
> $$
>
> processes.
>
> If it already has $p_i$, then the additional processes needed are
>
> $$
> \max(0, x t_i - p_i).
> $$
>
> The corresponding cost is
>
> $$
> \max(0, x t_i - p_i) \cdot c_i.
> $$
>
> Summing this over all services gives the minimum cost needed to achieve throughput $x$. If that total cost is at most the budget, then $x$ is feasible.
>
> Because feasibility is monotonic:
>
> - if $x$ is feasible, then every $y \le x$ is feasible;
> - if $x$ is not feasible, then every $y > x$ is not feasible.
>
> So binary search applies.
>
> ---
>
> ## Algorithm
>
> 1. Define a function `canAchieve(x)`:
>    - compute total cost required to make every service support throughput $x$;
>    - return whether total cost $\le$ budget.
>
> 2. Binary search the maximum feasible $x$.
>    - Start with:
>      - `low = 0`
>      - `high = 1`
>    - Double `high` until `canAchieve(high)` becomes false.
>    - Then binary search on $[low, high]$ for the largest feasible value.
>
> This avoids needing a problem-specific fixed upper bound.
>
> ---
>
> ## Correctness
>
> Let $f(x)$ be the minimum cost required to make all services support throughput $x$.
>
> For each service $i$,
>
> $$
> \text{cost}_i(x) = \max(0, x t_i - p_i)\, c_i,
> $$
>
> so
>
> $$
> f(x) = \sum_i \text{cost}_i(x).
> $$
>
> Since each $\text{cost}_i(x)$ is nondecreasing in $x$, $f(x)$ is also nondecreasing. Therefore:
>
> - if $f(x) \le B$, then $x$ is achievable;
> - if $f(x) > B$, then any larger throughput is also unachievable.
>
> Hence the feasible set is of the form
>
> $$
> \{0,1,2,\dots,T\}
> $$
>
> for some maximum $T$, and binary search correctly finds $T$.
>
> ---
>
> ## Time Complexity
>
> Let $n$ be the number of services.
>
> - Each feasibility check takes $O(n)$.
> - The binary search performs $O(\log T)$ checks, where $T$ is the answer range.
>
> Thus total complexity is
>
> $$
> O(n \log T).
> $$
>
> Space usage is
>
> $$
> O(1)
> $$
>
> besides the input storage.
>
> ---
>
> ## Java Implementation
>
> ```java
> import java.util.*;
>
> class Result {
>     public static long getMaxThroughput(List<Integer> processes,
>                                         List<Integer> throughput,
>                                         List<Integer> scalingCost,
>                                         long budget) {
>         int n = processes.size();
>
>         long low = 0;
>         long high = 1;
>
>         while (canAchieve(high, processes, throughput, scalingCost, budget, n)) {
>             high *= 2;
>         }
>
>         while (low < high) {
>             long mid = low + (high - low + 1) / 2;
>             if (canAchieve(mid, processes, throughput, scalingCost, budget, n)) {
>                 low = mid;
>             } else {
>                 high = mid - 1;
>             }
>         }
>
>         return low;
>     }
>
>     private static boolean canAchieve(long target,
>                                       List<Integer> processes,
>                                       List<Integer> throughput,
>                                       List<Integer> scalingCost,
>                                       long budget,
>                                       int n) {
>         long totalCost = 0;
>
>         for (int i = 0; i < n; i++) {
>             long required = target * (long) throughput.get(i);
>             long current = processes.get(i);
>
>             if (required > current) {
>                 long extra = required - current;
>                 totalCost += extra * (long) scalingCost.get(i);
>
>                 if (totalCost > budget) {
>                     return false;
>                 }
>             }
>         }
>
>         return totalCost <= budget;
>     }
> }
> ```
>
> ---
>
> ## Final Answer
>
> Use **binary search on the target throughput**. For a candidate throughput $x$, compute the total cost needed to raise each service from $p_i$ processes to at least $x t_i$ processes:
>
> $$
> \sum_i \max(0, x t_i - p_i)\, c_i.
> $$
>
> If this cost is within budget, $x$ is feasible. Since feasibility is monotonic, binary search yields the maximum throughput efficiently in
>
> $$
> O(n \log T)
> $$
>
> time.
