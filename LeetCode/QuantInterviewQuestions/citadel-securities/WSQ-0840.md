> [!example] Question 840 · Citadel Securities
> ## Software Engineer Interview

How does std::unordered\_map work in C++? Provide an example.

[Source](https://www.thewallstreetquants.com/ebook#p=841)

> [!success]- Solution (Click to expand)
> `std::unordered_map` is an associative container that stores key–value pairs and provides average-case constant-time lookup, insertion, and removal.
>
> ## Basic idea
>
> `std::unordered_map` is typically implemented as a **hash table**.
>
> - Each key is passed through a **hash function**.
> - The hash determines a **bucket** where the element should be stored.
> - To find a key, the container hashes the key again and searches only within the corresponding bucket.
>
> Because of this structure:
>
> - Average insertion: $O(1)$
> - Average lookup: $O(1)$
> - Average erase: $O(1)$
>
> In the worst case, if many keys collide into the same bucket, these operations can degrade to $O(n)$.
>
> ## Key properties
>
> An `std::unordered_map<Key, T>` stores elements of type:
>
> $$
> \texttt{std::pair<const Key, T>}
> $$
>
> where:
>
> - `Key` is the key type
> - `T` is the mapped value type
>
> Each key is unique. If a key already exists, inserting the same key again does not create a second entry.
>
> Unlike `std::map`, the elements are **not sorted**. Iteration order is unspecified.
>
> ## How hashing and collisions work
>
> Suppose the keys are strings. For a key such as `"apple"`:
>
> 1. The hash function computes a hash value.
> 2. The container maps that hash value to a bucket index.
> 3. The pair is stored in that bucket.
>
> If two different keys map to the same bucket, a **collision** occurs. The container must then store multiple elements in that bucket and compare keys using an equality predicate such as `std::equal_to<Key>`.
>
> Thus, `std::unordered_map` relies on:
>
> - a hash function
> - an equality comparison
>
> By default, the standard library provides these for common types such as integers and strings.
>
> ## Example
>
> ```cpp
> #include <iostream>
> #include <string>
> #include <unordered_map>
>
> int main() {
>     std::unordered_map<std::string, int> ages;
>
>     // Insert elements
>     ages["Alice"] = 30;
>     ages["Bob"] = 25;
>     ages["Charlie"] = 35;
>
>     // Access an element
>     std::cout << "Alice: " << ages["Alice"] << '\n';
>
>     // Find an element
>     auto it = ages.find("Bob");
>     if (it != ages.end()) {
>         std::cout << "Bob found, age = " << it->second << '\n';
>     }
>
>     // Erase an element
>     ages.erase("Charlie");
>
>     // Iterate through the map
>     for (const auto& entry : ages) {
>         std::cout << entry.first << " -> " << entry.second << '\n';
>     }
>
>     return 0;
> }
> ```
>
> ## Explanation of the example
>
> The declaration
>
> ```cpp
> std::unordered_map<std::string, int> ages;
> ```
>
> creates a hash table whose:
>
> - keys are `std::string`
> - values are `int`
>
> The statement
>
> ```cpp
> ages["Alice"] = 30;
> ```
>
> does the following:
>
> - if `"Alice"` is not present, it inserts the key
> - then it assigns the value `30`
>
> The expression
>
> ```cpp
> ages.find("Bob")
> ```
>
> searches for the key `"Bob"` and returns:
>
> - an iterator to the element if found
> - `ages.end()` if not found
>
> The loop
>
> ```cpp
> for (const auto& entry : ages)
> ```
>
> iterates over all key–value pairs, but the order is not guaranteed.
>
> ## Important note about `operator[]`
>
> For `std::unordered_map`, using
>
> ```cpp
> ages["David"]
> ```
>
> will insert `"David"` if it does not already exist, with a default-constructed value. For `int`, that default value is $0$.
>
> So this code:
>
> ```cpp
> std::cout << ages["David"] << '\n';
> ```
>
> will print $0$, and `"David"` will now exist in the map.
>
> If insertion is not desired, use `find()` or `at()` instead.
>
> ## Example with `at()`
>
> ```cpp
> #include <iostream>
> #include <string>
> #include <unordered_map>
>
> int main() {
>     std::unordered_map<std::string, int> ages{
>         {"Alice", 30},
>         {"Bob", 25}
>     };
>
>     std::cout << ages.at("Alice") << '\n'; // OK
>
>     // ages.at("Charlie") would throw std::out_of_range
> }
> ```
>
> ## Custom key types
>
> If a custom type is used as the key, a hash function and equality comparison must be provided.
>
> Example:
>
> ```cpp
> #include <iostream>
> #include <string>
> #include <unordered_map>
>
> struct Point {
>     int x;
>     int y;
>
>     bool operator==(const Point& other) const {
>         return x == other.x && y == other.y;
>     }
> };
>
> struct PointHash {
>     std::size_t operator()(const Point& p) const {
>         return std::hash<int>{}(p.x) ^ (std::hash<int>{}(p.y) << 1);
>     }
> };
>
> int main() {
>     std::unordered_map<Point, std::string, PointHash> points;
>
>     points[{1, 2}] = "A";
>     points[{3, 4}] = "B";
>
>     std::cout << points[{1, 2}] << '\n';
> }
> ```
>
> Here:
>
> - `Point` is the key type
> - `PointHash` computes the hash
> - `operator==` defines key equality
>
> ## Summary
>
> `std::unordered_map`:
>
> - stores unique key–value pairs
> - uses hashing rather than sorting
> - supports average-case $O(1)$ lookup, insertion, and deletion
> - does not preserve any sorted order
> - requires a hash function and equality comparison for keys
>
> It is preferred when fast key-based access is needed and key order does not matter.
