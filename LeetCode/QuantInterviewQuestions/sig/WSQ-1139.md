> ## Software Engineer Interview

Why do we use hashtables, and what is their time complexity?

> ## Hashtable: Purpose and Time Complexity
>
> A **hashtable** is a data structure used to store **key–value pairs** and to support very fast lookup, insertion, and deletion.
>
> ### Why we use a hashtable
>
> We use a hashtable when we want to:
>
> - **Find data quickly by a key**
> - **Insert new items efficiently**
> - **Delete items efficiently**
> - Implement structures such as:
>   - dictionaries
>   - maps
>   - symbol tables
>   - caches
>   - sets
>
> The main idea is to use a **hash function** that converts a key into an array index. This allows the data to be accessed directly, without scanning all elements.
>
> For example, instead of searching through a list of $n$ items one by one, a hashtable tries to go directly to the location where the key should be stored.
>
> ---
>
> ## How it works
>
> Given a key $k$, a hash function computes:
>
> $$
> h(k)
> $$
>
> which maps the key to an index in an array. The value associated with $k$ is stored at that index, or in a structure attached to that index.
>
> Because different keys may map to the same index, **collisions** can occur. Common ways to handle collisions are:
>
> - **Chaining**: each array slot stores a list of entries
> - **Open addressing**: probe other slots until an empty one is found
>
> ---
>
> ## Time complexity
>
> ### Average-case time complexity
>
> For a well-designed hashtable with a good hash function, the average time complexities are:
>
> - **Search**: $O(1)$
> - **Insert**: $O(1)$
> - **Delete**: $O(1)$
>
> This is the main reason hashtables are widely used.
>
> ---
>
> ### Worst-case time complexity
>
> In the worst case, many keys collide and operations may degrade to:
>
> - **Search**: $O(n)$
> - **Insert**: $O(n)$
> - **Delete**: $O(n)$
>
> where $n$ is the number of stored elements.
>
> This happens if:
>
> - the hash function is poor,
> - the table becomes too full,
> - or many keys hash to the same location.
>
> ---
>
> ## Space complexity
>
> A hashtable typically uses:
>
> $$
> O(n)
> $$
>
> space, though extra unused array space is often kept to maintain efficiency.
>
> ---
>
> ## Summary
>
> We use a hashtable because it provides very fast access to data by key. Its typical performance is:
>
> - **Average case**: $O(1)$ for search, insert, and delete
> - **Worst case**: $O(n)$ for search, insert, and delete
>
> Thus, a hashtable is preferred when fast key-based access is important.
