> [!example] Question 1140 · SIG
> ## Software Engineer Interview

What is a Binary Search Tree, and what is its time complexity for search, insert, and delete operations?

[Source](https://www.thewallstreetquants.com/ebook#p=1141)

> [!success]- Solution (Click to expand)
> ## Binary Search Tree
>
> A **Binary Search Tree (BST)** is a binary tree data structure in which each node stores a key, and the keys satisfy the **BST property**:
>
> - All keys in the left subtree of a node are **less than** the node’s key.
> - All keys in the right subtree are **greater than** the node’s key.
> - Both left and right subtrees are themselves binary search trees.
>
> If a node contains key $k$, then for every key $x$ in its left subtree and every key $y$ in its right subtree,
>
> $$
> x < k < y.
> $$
>
> This ordering property makes BSTs useful for efficient searching, insertion, and deletion.
>
> ---
>
> ## Basic Operations
>
> Let $h$ denote the height of the tree.
>
> ### 1. Search
> To search for a key $k$:
>
> - Start at the root.
> - If $k$ equals the current node’s key, the search succeeds.
> - If $k$ is smaller, move to the left child.
> - If $k$ is larger, move to the right child.
> - Repeat until the key is found or a null pointer is reached.
>
> Because each step moves down one level, the running time is proportional to the tree height.
>
> $$
> T_{\text{search}} = O(h)
> $$
>
> ---
>
> ### 2. Insertion
> To insert a key $k$:
>
> - Follow the same path as in search.
> - When a null position is reached, insert the new node there.
>
> Thus insertion also depends on the height of the tree.
>
> $$
> T_{\text{insert}} = O(h)
> $$
>
> ---
>
> ### 3. Deletion
> Deletion has three cases:
>
> - **Leaf node:** remove it directly.
> - **Node with one child:** replace the node by its child.
> - **Node with two children:** replace the node with its inorder successor or inorder predecessor, then delete that replacement node.
>
> Again, the operation requires traversing a path of length at most $h$.
>
> $$
> T_{\text{delete}} = O(h)
> $$
>
> ---
>
> ## Time Complexity
>
> The complexity depends on the height $h$ of the tree.
>
> ### Best / Average Case
> If the BST is approximately balanced, then its height is logarithmic in the number of nodes $n$:
>
> $$
> h = O(\log n)
> $$
>
> So the main operations take:
>
> $$
> \text{Search} = O(\log n), \quad
> \text{Insert} = O(\log n), \quad
> \text{Delete} = O(\log n)
> $$
>
> ### Worst Case
> If the tree becomes skewed, for example by inserting keys in sorted order, then the BST resembles a linked list. In that case,
>
> $$
> h = O(n)
> $$
>
> and therefore:
>
> $$
> \text{Search} = O(n), \quad
> \text{Insert} = O(n), \quad
> \text{Delete} = O(n)
> $$
>
> ---
>
> ## Traversal Complexity
>
> Common traversals include:
>
> - inorder
> - preorder
> - postorder
> - level-order
>
> Each traversal visits every node exactly once, so for $n$ nodes:
>
> $$
> T_{\text{traversal}} = O(n)
> $$
>
> ---
>
> ## Space Complexity
>
> A BST with $n$ nodes stores one node per key, so the space required is
>
> $$
> O(n)
> $$
>
> Recursive operations may also use call stack space proportional to the height:
>
> $$
> O(h)
> $$
>
> which is:
>
> - $O(\log n)$ for a balanced BST,
> - $O(n)$ for a skewed BST.
>
> ---
>
> ## Summary
>
> For a BST with $n$ nodes and height $h$:
>
> $$
> \text{Search} = O(h), \quad
> \text{Insert} = O(h), \quad
> \text{Delete} = O(h)
> $$
>
> Hence:
>
> - **Balanced BST:**  
>   $$
>   O(\log n)
>   $$
> - **Worst-case skewed BST:**  
>   $$
>   O(n)
>   $$
>
> Thus, a Binary Search Tree is efficient when it remains balanced, but its performance degrades significantly if it becomes unbalanced.
