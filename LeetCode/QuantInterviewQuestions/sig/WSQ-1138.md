> ## Software Developer Interview

What is garbage collection, and how is it performed in Java?

[Source](https://www.thewallstreetquants.com/ebook#p=1139)

> [!success]- Solution (Click to expand)
> ## Garbage Collection
>
> Garbage collection is the automatic process of identifying and reclaiming memory occupied by objects that are no longer reachable or needed by a program. Its purpose is to prevent memory leaks caused by forgotten deallocation and to make memory management safer and easier for the programmer.
>
> In languages with manual memory management, the programmer explicitly frees memory. In Java, this responsibility is handled automatically by the Java Virtual Machine (JVM).
>
> ## Basic Idea in Java
>
> In Java, objects are created on the heap using `new`. An object becomes eligible for garbage collection when it is no longer reachable by any live reference.
>
> An object is generally considered reachable if it can be accessed, directly or indirectly, from one of the following:
>
> - local variables in active methods
> - static fields
> - active threads
> - JNI references
>
> If no chain of references exists from these roots to an object, the object is treated as garbage.
>
> ## How Garbage Collection Is Done in Java
>
> Java uses an automatic garbage collector built into the JVM. The exact algorithm depends on the JVM and the selected collector, but the general process is as follows.
>
> ### $1.$ Marking
>
> The garbage collector begins from a set of root references and traverses the object graph.
>
> - reachable objects are marked as alive
> - unmarked objects are considered unreachable
>
> ### $2.$ Sweeping or Reclaiming
>
> After marking, memory occupied by unreachable objects is reclaimed.
>
> - some collectors simply remove unused objects
> - others compact memory by moving live objects together to reduce fragmentation
>
> ### $3.$ Compaction
>
> Many Java collectors compact the heap after reclaiming space. This means:
>
> - live objects may be moved
> - fragmented free memory is combined into larger contiguous blocks
> - references to moved objects are updated automatically by the JVM
>
> ## Generational Garbage Collection
>
> Java typically uses a **generational** approach, based on the observation that most objects die young.
>
> The heap is divided into generations:
>
> - **Young Generation**: newly created objects
> - **Old Generation**: long-lived objects
> - sometimes **Metaspace** for class metadata, though this is not regular object heap storage
>
> ### Young Generation Collection
>
> New objects are allocated in the young generation. When it fills up, a **minor garbage collection** occurs.
>
> - objects that are no longer referenced are removed
> - surviving objects may be moved
> - objects that survive several collections are promoted to the old generation
>
> ### Old Generation Collection
>
> Objects that remain alive for a long time are moved to the old generation. When this area becomes full, a **major garbage collection** or **full garbage collection** may occur.
>
> - this is usually more expensive than a minor collection
> - it examines a larger part of memory
>
> ## Common Garbage Collection Algorithms
>
> Java garbage collectors may use one or more of these techniques:
>
> - **Mark-Sweep**
> - **Mark-Compact**
> - **Copying**
> - **Generational Collection**
>
> Modern JVMs provide several collectors, such as:
>
> - Serial GC
> - Parallel GC
> - G1 GC
> - ZGC
> - Shenandoah
>
> They differ in throughput, pause time, and memory overhead.
>
> ## When Does an Object Become Eligible?
>
> An object may become eligible for garbage collection in situations such as:
>
> - its reference is set to `null`
> - the reference variable goes out of scope
> - the object is part of a group of objects that reference each other but are unreachable from any root
>
> Example:
>
> ```java
> Student s = new Student();
> s = null;
> ```
>
> Here, the `Student` object becomes eligible for garbage collection after `s` is set to `null`, assuming no other reference points to it.
>
> ## Can the Programmer Force Garbage Collection?
>
> The programmer cannot force garbage collection to occur at an exact time. Java only allows a **request**, for example through:
>
> ```java
> System.gc();
> ```
>
> or
>
> ```java
> Runtime.getRuntime().gc();
> ```
>
> However, the JVM is free to ignore this request.
>
> ## Finalization
>
> Older Java versions allowed a `finalize()` method to run before object reclamation. This mechanism is unreliable and deprecated, so it should not be relied upon for resource cleanup.
>
> Instead, Java uses:
>
> - `try-with-resources`
> - explicit closing of files, sockets, and database connections
>
> Garbage collection manages memory, not external resources.
>
> ## Conclusion
>
> Garbage collection is the JVM’s automatic memory recovery mechanism. In Java, it works by tracing reachable objects from root references, reclaiming memory used by unreachable objects, and often organizing memory using generational collection. This removes much of the burden of manual memory management from the programmer while improving safety and reliability.
