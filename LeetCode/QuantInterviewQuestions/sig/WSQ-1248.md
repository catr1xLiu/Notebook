> [!example] Question 1248 · SIG
> ## Technology Associate Interview

How could you implement several Java features, such as inheritance and abstract classes, in C?

[Source](https://www.thewallstreetquants.com/ebook#p=1249)

> [!success]- Solution (Click to expand)
> ## Implementing Java-Like Features in C
>
> C does not provide object-oriented features directly, but many of them can be simulated using structs, function pointers, disciplined memory layout, and conventions. The key idea is to represent an object as a struct and represent methods as functions or function pointers.
>
> ---
>
> ## 1. Classes and Objects
>
> A Java class can be modeled by a C `struct`, and an object is simply an instance of that struct.
>
> ### Java
> ```java
> class Point {
>     int x, y;
> }
> ```
>
> ### C
> ```c
> typedef struct {
>     int x;
>     int y;
> } Point;
> ```
>
> An object:
> ```c
> Point p = {1, 2};
> ```
>
> ---
>
> ## 2. Methods
>
> Java methods can be implemented as ordinary C functions that take a pointer to the object as their first argument, similar to the implicit `this` reference in Java.
>
> ### Java
> ```java
> class Point {
>     int x, y;
>     void move(int dx, int dy) {
>         x += dx;
>         y += dy;
>     }
> }
> ```
>
> ### C
> ```c
> #include <stdio.h>
>
> typedef struct {
>     int x;
>     int y;
> } Point;
>
> void Point_move(Point *this, int dx, int dy) {
>     this->x += dx;
>     this->y += dy;
> }
> ```
>
> Here, `this` is passed explicitly.
>
> ---
>
> ## 3. Encapsulation
>
> C has no access modifiers such as `private`, `protected`, or `public`. Encapsulation is approximated by hiding struct definitions in source files and exposing only incomplete types in header files.
>
> ### Header file
> ```c
> typedef struct Point Point;
>
> Point *Point_new(int x, int y);
> void Point_move(Point *p, int dx, int dy);
> void Point_print(const Point *p);
> void Point_delete(Point *p);
> ```
>
> ### Source file
> ```c
> #include <stdio.h>
> #include <stdlib.h>
>
> struct Point {
>     int x;
>     int y;
> };
>
> Point *Point_new(int x, int y) {
>     Point *p = malloc(sizeof(Point));
>     p->x = x;
>     p->y = y;
>     return p;
> }
>
> void Point_move(Point *p, int dx, int dy) {
>     p->x += dx;
>     p->y += dy;
> }
>
> void Point_print(const Point *p) {
>     printf("(%d, %d)\n", p->x, p->y);
> }
>
> void Point_delete(Point *p) {
>     free(p);
> }
> ```
>
> This hides the internal representation from users of the module.
>
> ---
>
> ## 4. Constructors and Destructors
>
> Java constructors become initialization functions or allocation functions in C.
>
> ### C style
> ```c
> Point *Point_new(int x, int y);
> void Point_init(Point *p, int x, int y);
> void Point_delete(Point *p);
> ```
>
> - `Point_new` allocates and initializes.
> - `Point_init` initializes an already allocated object.
> - `Point_delete` releases memory.
>
> C has no garbage collection, so destruction must be done explicitly.
>
> ---
>
> ## 5. Inheritance
>
> Inheritance can be simulated by embedding the base struct as the first member of the derived struct. This ensures that a pointer to the derived object can be cast to a pointer to the base object.
>
> ### Java
> ```java
> class Animal {
>     String name;
> }
>
> class Dog extends Animal {
>     int age;
> }
> ```
>
> ### C
> ```c
> typedef struct {
>     const char *name;
> } Animal;
>
> typedef struct {
>     Animal base;
>     int age;
> } Dog;
> ```
>
> Because `base` is the first field, a `Dog *` can be treated as an `Animal *`:
>
> ```c
> Dog d = {{ "Buddy" }, 5};
> Animal *a = (Animal *)&d;
> ```
>
> This mimics the "`is-a`" relationship.
>
> ---
>
> ## 6. Method Overriding and Dynamic Dispatch
>
> To simulate virtual methods, use a table of function pointers, often called a vtable.
>
> ### Step 1: Define the base type and vtable
> ```c
> #include <stdio.h>
> #include <stdlib.h>
>
> typedef struct Animal Animal;
> typedef struct AnimalVTable AnimalVTable;
>
> struct AnimalVTable {
>     void (*speak)(Animal *this);
> };
>
> struct Animal {
>     const AnimalVTable *vptr;
>     const char *name;
> };
> ```
>
> ### Step 2: Define derived types
> ```c
> typedef struct {
>     Animal base;
> } Dog;
>
> typedef struct {
>     Animal base;
> } Cat;
> ```
>
> ### Step 3: Implement methods
> ```c
> void Dog_speak(Animal *this) {
>     printf("%s says: Woof!\n", this->name);
> }
>
> void Cat_speak(Animal *this) {
>     printf("%s says: Meow!\n", this->name);
> }
> ```
>
> ### Step 4: Define vtables
> ```c
> const AnimalVTable dog_vtable = { Dog_speak };
> const AnimalVTable cat_vtable = { Cat_speak };
> ```
>
> ### Step 5: Constructors
> ```c
> void Dog_init(Dog *d, const char *name) {
>     d->base.vptr = &dog_vtable;
>     d->base.name = name;
> }
>
> void Cat_init(Cat *c, const char *name) {
>     c->base.vptr = &cat_vtable;
>     c->base.name = name;
> }
> ```
>
> ### Step 6: Dynamic dispatch
> ```c
> void Animal_speak(Animal *a) {
>     a->vptr->speak(a);
> }
> ```
>
> ### Usage
> ```c
> int main(void) {
>     Dog d;
>     Cat c;
>
>     Dog_init(&d, "Buddy");
>     Cat_init(&c, "Kitty");
>
>     Animal *animals[2];
>     animals[0] = (Animal *)&d;
>     animals[1] = (Animal *)&c;
>
>     for (int i = 0; i < 2; i++) {
>         Animal_speak(animals[i]);
>     }
>
>     return 0;
> }
> ```
>
> This gives polymorphic behavior similar to Java method overriding.
>
> ---
>
> ## 7. Abstract Classes
>
> An abstract class in Java is a class that cannot be instantiated directly and may contain abstract methods. In C, this can be modeled by:
>
> 1. Defining a base struct,
> 2. Giving it a vtable with required function pointers,
> 3. Never providing a constructor for the base type.
>
> ### Example
> ```c
> typedef struct Shape Shape;
> typedef struct ShapeVTable ShapeVTable;
>
> struct ShapeVTable {
>     double (*area)(Shape *this);
> };
>
> struct Shape {
>     const ShapeVTable *vptr;
> };
> ```
>
> Derived classes:
> ```c
> typedef struct {
>     Shape base;
>     double radius;
> } Circle;
>
> typedef struct {
>     Shape base;
>     double width;
>     double height;
> } Rectangle;
> ```
>
> Implementations:
> ```c
> double Circle_area(Shape *this) {
>     Circle *c = (Circle *)this;
>     return 3.141592653589793 * c->radius * c->radius;
> }
>
> double Rectangle_area(Shape *this) {
>     Rectangle *r = (Rectangle *)this;
>     return r->width * r->height;
> }
> ```
>
> Vtables:
> ```c
> const ShapeVTable circle_vtable = { Circle_area };
> const ShapeVTable rectangle_vtable = { Rectangle_area };
> ```
>
> Constructors:
> ```c
> void Circle_init(Circle *c, double radius) {
>     c->base.vptr = &circle_vtable;
>     c->radius = radius;
> }
>
> void Rectangle_init(Rectangle *r, double w, double h) {
>     r->base.vptr = &rectangle_vtable;
>     r->width = w;
>     r->height = h;
> }
> ```
>
> Abstract dispatch:
> ```c
> double Shape_area(Shape *s) {
>     return s->vptr->area(s);
> }
> ```
>
> The `Shape` type is effectively abstract because it is meaningless to instantiate it without a valid vtable implementation.
>
> ---
>
> ## 8. Interfaces
>
> A Java interface can be represented by a separate vtable-like contract. A type "implements" the interface by providing the necessary function pointers.
>
> ### Example: `Drawable`
> ```c
> typedef struct Drawable Drawable;
> typedef struct DrawableVTable DrawableVTable;
>
> struct DrawableVTable {
>     void (*draw)(Drawable *this);
> };
>
> struct Drawable {
>     const DrawableVTable *vptr;
> };
> ```
>
> A concrete object can contain both its own data and a compatible interface header, or expose adapter functions. In practice, this is more cumbersome than in Java, but the principle is the same: an interface is a struct plus a table of required operations.
>
> ---
>
> ## 9. Single vs. Multiple Inheritance
>
> ### Single inheritance
> Single inheritance is relatively straightforward with struct embedding.
>
> ### Multiple inheritance
> True multiple inheritance is difficult in C because it requires multiple base subobjects and pointer adjustment. It is usually better to simulate it with interfaces or composition.
>
> Thus:
>
> - Use embedded base structs for inheritance.
> - Use separate function-pointer interfaces for shared capabilities.
> - Prefer composition when possible.
>
> ---
>
> ## 10. Overloading
>
> Java allows method overloading by argument types. C does not support this directly. Common substitutes are:
>
> - Different function names:
> ```c
> void print_int(int x);
> void print_double(double x);
> ```
>
> - Macros with `_Generic` in modern C:
> ```c
> #define print(x) _Generic((x), \
>     int: print_int, \
>     double: print_double \
> )(x)
> ```
>
> This approximates compile-time overloading.
>
> ---
>
> ## 11. Static Members
>
> Java static fields and methods correspond naturally to global variables and ordinary functions in C.
>
> ### Java
> ```java
> class Counter {
>     static int count = 0;
> }
> ```
>
> ### C
> ```c
> int Counter_count = 0;
> ```
>
> A static method:
> ```c
> void Counter_reset(void) {
>     Counter_count = 0;
> }
> ```
>
> If the symbol should be private to one source file, use the C `static` keyword at file scope.
>
> ---
>
> ## 12. Packages and Namespaces
>
> C has no namespace mechanism like Java packages. The standard convention is to prefix names.
>
> For example:
>
> - `Point_new`
> - `Point_move`
> - `Animal_speak`
>
> This reduces naming collisions and acts as a manual namespace.
>
> ---
>
> ## 13. Exceptions
>
> Java exceptions do not have a direct equivalent in C. Common techniques are:
>
> - Return error codes,
> - Use output parameters for results,
> - Set a global or thread-local error variable,
> - In rare cases, use `setjmp` and `longjmp`.
>
> Example:
> ```c
> int divide(int a, int b, int *result) {
>     if (b == 0) return -1;
>     *result = a / b;
>     return 0;
> }
> ```
>
> This is much closer to traditional systems programming style than Java exception handling.
>
> ---
>
> ## 14. A Complete Example
>
> The following example combines inheritance, abstract classes, and polymorphism.
>
> ```c
> #include <stdio.h>
>
> typedef struct Shape Shape;
> typedef struct ShapeVTable ShapeVTable;
>
> struct ShapeVTable {
>     double (*area)(Shape *this);
>     void (*print)(Shape *this);
> };
>
> struct Shape {
>     const ShapeVTable *vptr;
> };
>
> double Shape_area(Shape *s) {
>     return s->vptr->area(s);
> }
>
> void Shape_print(Shape *s) {
>     s->vptr->print(s);
> }
>
> typedef struct {
>     Shape base;
>     double radius;
> } Circle;
>
> typedef struct {
>     Shape base;
>     double width;
>     double height;
> } Rectangle;
>
> double Circle_area(Shape *this) {
>     Circle *c = (Circle *)this;
>     return 3.141592653589793 * c->radius * c->radius;
> }
>
> void Circle_print(Shape *this) {
>     Circle *c = (Circle *)this;
>     printf("Circle(radius=%.2f)", c->radius);
> }
>
> double Rectangle_area(Shape *this) {
>     Rectangle *r = (Rectangle *)this;
>     return r->width * r->height;
> }
>
> void Rectangle_print(Shape *this) {
>     Rectangle *r = (Rectangle *)this;
>     printf("Rectangle(width=%.2f, height=%.2f)", r->width, r->height);
> }
>
> const ShapeVTable circle_vtable = {
>     Circle_area,
>     Circle_print
> };
>
> const ShapeVTable rectangle_vtable = {
>     Rectangle_area,
>     Rectangle_print
> };
>
> void Circle_init(Circle *c, double radius) {
>     c->base.vptr = &circle_vtable;
>     c->radius = radius;
> }
>
> void Rectangle_init(Rectangle *r, double width, double height) {
>     r->base.vptr = &rectangle_vtable;
>     r->width = width;
>     r->height = height;
> }
>
> int main(void) {
>     Circle c;
>     Rectangle r;
>
>     Circle_init(&c, 2.0);
>     Rectangle_init(&r, 3.0, 4.0);
>
>     Shape *shapes[2];
>     shapes[0] = (Shape *)&c;
>     shapes[1] = (Shape *)&r;
>
>     for (int i = 0; i < 2; i++) {
>         Shape_print(shapes[i]);
>         printf(", area = %.2f\n", Shape_area(shapes[i]));
>     }
>
>     return 0;
> }
> ```
>
> This demonstrates:
>
> - `Shape` as an abstract base class,
> - `Circle` and `Rectangle` as subclasses,
> - virtual methods via function pointers,
> - polymorphic calls through `Shape *`.
>
> ---
>
> ## 15. Summary
>
> Java features can be approximated in C as follows:
>
> - **Class** $\to$ `struct`
> - **Object** $\to$ struct instance or heap-allocated struct
> - **Method** $\to$ function with explicit `this` pointer
> - **Encapsulation** $\to$ opaque pointers and hidden struct definitions
> - **Constructor/destructor** $\to$ `init`, `new`, `delete`
> - **Inheritance** $\to$ embed base struct as first field
> - **Polymorphism** $\to$ vtables using function pointers
> - **Abstract class** $\to$ base struct with required function pointers and no direct constructor
> - **Interface** $\to$ separate operation table or adapter pattern
> - **Static members** $\to$ global variables/functions
> - **Exceptions** $\to$ error codes or `setjmp`/`longjmp`
>
> Thus, although C is not object-oriented, disciplined use of structs and function pointers allows many Java-like features to be implemented manually.
