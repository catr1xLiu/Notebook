> [!example] Question 976 · Optiver
> ## Graduate Software Developer Interview

What is the use of atomic operations in multiprocessing?

[Source](https://www.thewallstreetquants.com/ebook#p=977)

> [!success]- Solution (Click to expand)
> In multiprocessing, an **atomic operation** is used to ensure that a read-modify-write action on shared data happens as a single, indivisible step. This prevents race conditions when multiple processes access or update the same memory concurrently.
>
> ## Why atomic operations are needed
>
> When several processes share a variable, an apparently simple statement such as
>
> $$x = x + 1$$
>
> is not actually a single step. It typically consists of:
>
> 1. reading the current value of $x$,
> 2. computing $x + 1$,
> 3. writing the new value back.
>
> If two processes do this at the same time, they may both read the same old value and overwrite each other’s updates. This causes incorrect results.
>
> ## Use of atomic operations
>
> Atomic operations are used to:
>
> - **prevent race conditions** on shared variables,
> - **maintain data consistency** without corruption,
> - **safely increment, decrement, swap, or compare-and-update values**,
> - **build synchronization primitives** such as locks, semaphores, and mutexes.
>
> ## Example
>
> Suppose two processes both execute an increment on a shared counter initially equal to $0$.
>
> Without atomicity:
>
> - Process $A$ reads $0$,
> - Process $B$ reads $0$,
> - Process $A$ writes $1$,
> - Process $B$ writes $1$.
>
> The final value is $1$, even though two increments occurred.
>
> With an atomic increment, the two operations are serialized at the hardware or system level, so the final value becomes $2$.
>
> ## In multiprocessing specifically
>
> Because processes run independently and may truly execute in parallel on different CPU cores, atomic operations are important whenever they share memory. They are commonly used in:
>
> - shared counters,
> - reference counts,
> - lock-free data structures,
> - inter-process coordination.
>
> ## Conclusion
>
> The purpose of atomic operations in multiprocessing is to make updates to shared data **safe and indivisible**, so that concurrent processes do not interfere with one another and produce incorrect results.
