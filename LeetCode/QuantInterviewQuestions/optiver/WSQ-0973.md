> [!example] Question 973 · Optiver
> ## Senior Software Developer Interview

Given two very large integers represented as strings, implement multiplication of these numbers. You cannot use built-in big integer libraries. You must represent the digits as strings, implement addition of two strings, and then use that method as part of your multiplication function. How would you handle carries correctly in your implementation?

[Source](https://www.thewallstreetquants.com/ebook#p=974)

> [!success]- Solution (Click to expand)
> ## Solution
>
> Since the input integers can be much larger than the built-in numeric types can store, the numbers must be handled as strings. The idea is to simulate the usual grade-school algorithms:
>
> 1. **Addition of two nonnegative integers stored as strings**, used as a building block.
> 2. **Multiplication of two nonnegative integers stored as strings**, built directly on top of string addition: each digit of one number produces a shifted partial product, and the partial products are accumulated using the string-addition routine.
>
> ---
>
> ## 1. String addition
>
> Let the two numbers be $a$ and $b$, stored as strings.
>
> ### Method
> Process the strings from right to left:
>
> - Let $i$ point to the last digit of $a$,
> - Let $j$ point to the last digit of $b$,
> - Maintain a carry $c$.
>
> At each step:
>
> - Convert the current characters to digits,
> - Compute
>   $$
>   s = d_a + d_b + c,
>   $$
> - Append the digit
>   $$
>   s \bmod 10
>   $$
>   to the answer,
> - Update
>   $$
>   c = \left\lfloor \frac{s}{10} \right\rfloor.
>   $$
>
> After processing all digits, if $c > 0$, append it as well. Since digits were produced from least significant to most significant, reverse the result at the end.
>
> ### Complexity
> If $n = |a|$ and $m = |b|$, then addition runs in
> $$
> O(\max(n,m)).
> $$
>
> ---
>
> ## 2. String multiplication built from string addition
>
> Let $a$ have $n$ digits and $b$ have $m$ digits. The grade-school method multiplies $a$ by each digit of $b$ in turn, shifts each such partial product into its correct place value, and adds the shifted partial products together — using the addition routine from Part 1 to perform every one of those additions.
>
> ### Multiplying a string by a single digit
>
> As a building block, multiply the string $a$ by one digit $d$, processing $a$ from right to left with a carry, exactly as in ordinary long multiplication by a single digit:
>
> $$
> p = (a[i]-\texttt{'0'})\cdot d + c, \qquad \text{digit } p \bmod 10,\qquad c = \left\lfloor \frac{p}{10}\right\rfloor.
> $$
>
> This produces a string representing $a\cdot d$ in
>
> $$
> O(n)
> $$
>
> time.
>
> ### Combining the partial products
>
> Processing the digits of $b$ from least significant to most significant, the $k$-th digit from the right of $b$ (counting from $k=0$) contributes the partial product
>
> $$
> a \cdot b[k] \cdot 10^{k},
> $$
>
> which is obtained by multiplying $a$ by that single digit and appending $k$ zeros to the resulting string. Each such shifted partial product is then folded into a running total using `addStrings`:
>
> $$
> \text{result} \leftarrow \text{addStrings}(\text{result},\ \text{shiftedPartialProduct}).
> $$
>
> After all $m$ digits of $b$ have been processed this way, `result` holds the product $a\cdot b$.
>
> ### Why this works
>
> This is exactly the standard grade-school algorithm for multiplying by hand: each digit of $b$ produces one shifted row, and the rows are summed. Expressing the summation step as repeated calls to `addStrings` reuses the addition routine already built in Part 1, rather than re-deriving carry propagation from scratch for multiplication.
>
> ### Complexity
>
> There are $m$ digits in $b$, so $m$ single-digit multiplications are performed, each costing $O(n)$, and $m$ calls to `addStrings`, each on strings of length $O(n+m)$. The total running time is therefore
>
> $$
> O\big(m(n+m)\big),
> $$
>
> which, taking $b$ to be the shorter of the two numbers, is $O(nm)$.
>
> ---
>
> ## 3. C++ implementation
>
> ```cpp
> #include <bits/stdc++.h>
> using namespace std;
>
> string addStrings(const string &a, const string &b) {
>     int i = (int)a.size() - 1;
>     int j = (int)b.size() - 1;
>     int carry = 0;
>     string ans;
>
>     while (i >= 0 || j >= 0 || carry) {
>         int x = (i >= 0 ? a[i] - '0' : 0);
>         int y = (j >= 0 ? b[j] - '0' : 0);
>         int sum = x + y + carry;
>         ans.push_back(char('0' + (sum % 10)));
>         carry = sum / 10;
>         i--;
>         j--;
>     }
>
>     reverse(ans.begin(), ans.end());
>     return ans;
> }
>
> string multiplyBySingleDigit(const string &a, int d) {
>     if (d == 0) return "0";
>
>     string ans;
>     int carry = 0;
>     for (int i = (int)a.size() - 1; i >= 0; i--) {
>         int x = a[i] - '0';
>         int prod = x * d + carry;
>         ans.push_back(char('0' + (prod % 10)));
>         carry = prod / 10;
>     }
>     while (carry > 0) {
>         ans.push_back(char('0' + (carry % 10)));
>         carry /= 10;
>     }
>
>     reverse(ans.begin(), ans.end());
>     return ans;
> }
>
> string multiplyStrings(const string &a, const string &b) {
>     if (a == "0" || b == "0") return "0";
>
>     string result = "0";
>     int m = (int)b.size();
>
>     for (int j = m - 1; j >= 0; j--) {
>         int d = b[j] - '0';
>         string partial = multiplyBySingleDigit(a, d);
>         if (partial != "0") {
>             partial.append(m - 1 - j, '0');
>         }
>         result = addStrings(result, partial);
>     }
>
>     return result;
> }
>
> int main() {
>     string a, b;
>     cin >> a >> b;
>     cout << multiplyStrings(a, b) << '\n';
>     return 0;
> }
> ```
>
> ### Worked example
>
> Multiplying $a=\text{"123"}$ by $b=\text{"456"}$:
>
> - digit $6$ (shift $0$): $123\times 6=738$, partial $=\text{"738"}$, running result $=\text{addStrings}(\text{"0"},\text{"738"})=\text{"738"}$;
> - digit $5$ (shift $1$): $123\times 5=615$, shifted partial $=\text{"6150"}$, running result $=\text{addStrings}(\text{"738"},\text{"6150"})=\text{"6888"}$;
> - digit $4$ (shift $2$): $123\times 4=492$, shifted partial $=\text{"49200"}$, running result $=\text{addStrings}(\text{"6888"},\text{"49200"})=\text{"56088"}$.
>
> This matches $123\times 456=56088$.
>
> ---
>
> ## 4. Remark: an array-based alternative
>
> A common alternative, once one is no longer required to route the summation through `addStrings`, is to accumulate every digit product directly into a shared integer array of size $n+m$, where the product of $a[i]$ and $b[j]$ (indexed from the left) is added into position $i+j+1$ with its carry folded into position $i+j$. This avoids allocating and adding $m$ separate partial-product strings, and is somewhat more efficient in practice, but it re-derives carry propagation for multiplication directly rather than reusing the string-addition routine. Both approaches run in $O(nm)$ time; the array-based version simply has a smaller constant factor.
>
> ---
>
> ## Final answer
>
> Represent the integers as strings and implement addition by simulating the standard right-to-left carry process. Build multiplication on top of that addition routine: multiply the first number by each digit of the second, shift each resulting partial product into its correct place value, and accumulate the shifted partial products with repeated calls to the string-addition function. This yields a correct solution for arbitrarily large integers in
>
> $$
> O(nm)
> $$
>
> time (taking $n\ge m$), and
>
> $$
> O(n+m)
> $$
>
> space.
