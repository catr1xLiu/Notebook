> # Implementing a Queue
>
> A queue is a linear data structure that follows the **FIFO** principle: **first in, first out**. The element inserted first is removed first.
>
> ## Core operations
>
> A queue typically supports the following operations:
>
> - **Enqueue**: insert an element at the rear.
> - **Dequeue**: remove an element from the front.
> - **Front/Peek**: inspect the front element without removing it.
> - **isEmpty**: check whether the queue contains no elements.
> - **Size**: return the number of elements.
>
> ## Approach 1: Array-based implementation
>
> Use an array and track the positions of the front and rear.
>
> ### Basic idea
>
> Maintain:
>
> - an array `data`
> - an index `front`
> - an index `rear`
> - optionally a variable `size`
>
> When enqueuing, place the new element at the rear and move `rear` forward. When dequeuing, remove the element at the front and move `front` forward.
>
> ### Simple version
>
> This is easy to understand, but if elements are repeatedly dequeued, unused space accumulates at the beginning of the array.
>
> ```python
> class Queue:
>     def __init__(self):
>         self.data = []
>         self.front_index = 0
>
>     def enqueue(self, value):
>         self.data.append(value)
>
>     def dequeue(self):
>         if self.is_empty():
>             raise IndexError("queue is empty")
>         value = self.data[self.front_index]
>         self.front_index += 1
>         return value
>
>     def front(self):
>         if self.is_empty():
>             raise IndexError("queue is empty")
>         return self.data[self.front_index]
>
>     def is_empty(self):
>         return self.front_index >= len(self.data)
>
>     def size(self):
>         return len(self.data) - self.front_index
> ```
>
> ### Drawback
>
> Although `enqueue` is efficient, the array may keep old unused elements. To avoid this, one can periodically rebuild the array or use a **circular buffer**.
>
> ## Approach 2: Circular array implementation
>
> A circular array reuses freed space by wrapping indices around to the beginning.
>
> ### Representation
>
> Maintain:
>
> - fixed-size array `data`
> - integer `front`
> - integer `size`
>
> The rear position is computed as:
>
> $$
> \text{rear} = (\text{front} + \text{size}) \bmod \text{capacity}
> $$
>
> ### Operations
>
> #### Enqueue
>
> 1. Check whether the queue is full.
> 2. Compute the insertion index.
> 3. Store the element.
> 4. Increase `size`.
>
> #### Dequeue
>
> 1. Check whether the queue is empty.
> 2. Read the element at `front`.
> 3. Move `front` one step circularly.
> 4. Decrease `size`.
>
> ### Example
>
> ```python
> class CircularQueue:
>     def __init__(self, capacity):
>         self.data = [None] * capacity
>         self.front_index = 0
>         self.size_value = 0
>         self.capacity = capacity
>
>     def enqueue(self, value):
>         if self.size_value == self.capacity:
>             raise OverflowError("queue is full")
>         rear = (self.front_index + self.size_value) % self.capacity
>         self.data[rear] = value
>         self.size_value += 1
>
>     def dequeue(self):
>         if self.is_empty():
>             raise IndexError("queue is empty")
>         value = self.data[self.front_index]
>         self.data[self.front_index] = None
>         self.front_index = (self.front_index + 1) % self.capacity
>         self.size_value -= 1
>         return value
>
>     def front(self):
>         if self.is_empty():
>             raise IndexError("queue is empty")
>         return self.data[self.front_index]
>
>     def is_empty(self):
>         return self.size_value == 0
>
>     def size(self):
>         return self.size_value
> ```
>
> ### Time complexity
>
> For the circular array version:
>
> - `enqueue`: $O(1)$
> - `dequeue`: $O(1)$
> - `front`: $O(1)$
>
> ## Approach 3: Linked-list implementation
>
> A queue can also be implemented with a singly linked list. This is often the cleanest dynamic implementation.
>
> ### Representation
>
> Each node stores:
>
> - a value
> - a pointer to the next node
>
> The queue stores:
>
> - `head`: front of the queue
> - `tail`: rear of the queue
> - `size`
>
> ### Why this works
>
> - Enqueue at the tail in $O(1)$
> - Dequeue from the head in $O(1)$
>
> ### Example
>
> ```python
> class Node:
>     def __init__(self, value):
>         self.value = value
>         self.next = None
>
>
> class LinkedQueue:
>     def __init__(self):
>         self.head = None
>         self.tail = None
>         self.size_value = 0
>
>     def enqueue(self, value):
>         node = Node(value)
>         if self.tail is None:
>             self.head = self.tail = node
>         else:
>             self.tail.next = node
>             self.tail = node
>         self.size_value += 1
>
>     def dequeue(self):
>         if self.is_empty():
>             raise IndexError("queue is empty")
>         value = self.head.value
>         self.head = self.head.next
>         if self.head is None:
>             self.tail = None
>         self.size_value -= 1
>         return value
>
>     def front(self):
>         if self.is_empty():
>             raise IndexError("queue is empty")
>         return self.head.value
>
>     def is_empty(self):
>         return self.head is None
>
>     def size(self):
>         return self.size_value
> ```
>
> ### Time complexity
>
> For the linked-list version:
>
> - `enqueue`: $O(1)$
> - `dequeue`: $O(1)$
> - `front`: $O(1)$
>
> ## Choosing an implementation
>
> - Use an **array** if the maximum size is known and compact storage is important.
> - Use a **circular array** for efficient fixed-capacity queues.
> - Use a **linked list** when the queue size changes dynamically and no fixed capacity is desired.
>
> ## Summary
>
> To implement a queue, store elements so that insertion happens at the rear and removal happens at the front. The most common efficient choices are:
>
> - a **circular array** for fixed-size queues
> - a **linked list** for dynamic-size queues
>
> In both cases, the main queue operations can be supported in $O(1)$ time.
