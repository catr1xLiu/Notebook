> [!example] Question 922 · Optiver
> ## Software Engineer Interview

Complete a function that takes in a seqId (int) and a character (from 'a' to 'z' or '-'), where seqIds may arrive out of order. When the collected characters, sorted by seqId, form a complete message in the format '-FullMessage-', the function should print the message immediately using the provided OnComplete(msg) function.

[Source](https://www.thewallstreetquants.com/ebook#p=923)

> [!success]- Solution (Click to expand)
> ## Solution
>
> Process the stream incrementally while keeping enough state to reconstruct contiguous portions of the sequence despite out-of-order arrivals.
>
> A completed message has the form
>
> $$
> \texttt{-FullMessage-}
> $$
>
> so a message is complete exactly when, after sorting by `seqId`, there is a contiguous block that starts with `'-'`, ends with `'-'`, and contains all intermediate sequence ids.
>
> The main difficulty is that characters arrive out of order. Therefore, after each insertion, it must be possible to determine whether the new character connects previously separate contiguous blocks and whether one of those blocks now forms a complete message.
>
> ---
>
> ## Idea
>
> Maintain disjoint contiguous segments of known characters.
>
> Each segment represents an interval
>
> $$
> [L, R]
> $$
>
> such that every sequence id in that interval has been received. For each segment, also store the corresponding string.
>
> When a new pair $(\texttt{seqId}, \texttt{ch})$ arrives:
>
> 1. Ignore it if that `seqId` was already seen.
> 2. Create a length-$1$ segment $[\texttt{seqId}, \texttt{seqId}]$.
> 3. If there is a segment ending at $\texttt{seqId} - 1$, merge with it.
> 4. If there is a segment starting at $\texttt{seqId} + 1$, merge with it.
> 5. After merging, the resulting segment is maximal and contiguous.
> 6. If its first and last characters are both `'-'` and its length is at least $2$, then it is a complete message, so call `OnComplete`.
>
> To support efficient merges, keep two hash maps:
>
> - `startMap[L] = segment starting at L`
> - `endMap[R] = segment ending at R`
>
> Also keep a set of seen sequence ids to suppress duplicates.
>
> ---
>
> ## Correctness
>
> Let a segment represent exactly the sorted characters for a contiguous interval of received sequence ids.
>
> ### Invariant
> After every insertion:
>
> 1. Every received `seqId` belongs to exactly one segment.
> 2. Each segment corresponds to a maximal contiguous interval of received sequence ids.
> 3. The string stored in a segment is exactly the characters of that interval in increasing `seqId` order.
>
> This holds initially since there are no segments.
>
> When a new character at id $x$ arrives, there are only four possibilities:
>
> - no adjacent segments at $x-1$ or $x+1$,
> - only a left-adjacent segment,
> - only a right-adjacent segment,
> - both left- and right-adjacent segments.
>
> In each case, merging creates exactly the maximal contiguous interval containing $x$, preserves sorted order of characters, and leaves all other segments unchanged. Thus the invariant is maintained.
>
> ### Why message detection is correct
> A full message is present exactly when there exists a contiguous interval of received sequence ids whose sorted characters form a string beginning and ending with `'-'`.
>
> By the invariant, every maximal contiguous interval is represented by one segment. Therefore, after insertion, if a message has just become complete, it must be the segment produced by the merge involving the new character. Checking that segment’s first and last characters is therefore sufficient.
>
> Thus `OnComplete` is called exactly when a full message completes.
>
> ---
>
> ## Implementation
>
> ```cpp
> #include <string>
> #include <unordered_map>
> #include <unordered_set>
> using namespace std;
>
> // Provided externally.
> void OnComplete(const string& msg);
>
> class MessageAssembler {
> private:
>     struct Segment {
>         int l, r;
>         string s;
>         Segment(int L, int R, string str) : l(L), r(R), s(std::move(str)) {}
>     };
>
>     unordered_map<int, Segment*> startMap;   // start id -> segment
>     unordered_map<int, Segment*> endMap;     // end id   -> segment
>     unordered_set<int> seen;                 // deduplicate seqId
>
> public:
>     void AddChar(int seqId, char ch) {
>         if (seen.count(seqId)) return;
>         seen.insert(seqId);
>
>         Segment* cur = new Segment(seqId, seqId, string(1, ch));
>
>         // Merge with left segment if it ends at seqId - 1.
>         auto itLeft = endMap.find(seqId - 1);
>         if (itLeft != endMap.end()) {
>             Segment* left = itLeft->second;
>
>             endMap.erase(left->r);
>             startMap.erase(cur->l);
>
>             left->r = cur->r;
>             left->s += cur->s;
>
>             delete cur;
>             cur = left;
>             startMap[cur->l] = cur;
>             endMap[cur->r] = cur;
>         } else {
>             startMap[cur->l] = cur;
>             endMap[cur->r] = cur;
>         }
>
>         // Merge with right segment if it starts at seqId + 1.
>         auto itRight = startMap.find(cur->r + 1);
>         if (itRight != startMap.end()) {
>             Segment* right = itRight->second;
>
>             startMap.erase(right->l);
>             endMap.erase(cur->r);
>
>             cur->r = right->r;
>             cur->s += right->s;
>
>             endMap[cur->r] = cur;
>             delete right;
>         }
>
>         // cur is now the maximal contiguous segment containing seqId.
>         if (cur->s.size() >= 2 && cur->s.front() == '-' && cur->s.back() == '-') {
>             OnComplete(cur->s);
>
>             // Optional: remove completed segment if messages are disjoint
>             // and should not be reported again.
>             startMap.erase(cur->l);
>             endMap.erase(cur->r);
>             for (int i = cur->l; i <= cur->r; ++i) {
>                 seen.erase(i);
>             }
>             delete cur;
>         }
>     }
> };
> ```
>
> ---
>
> ## Notes
>
> ### Duplicate arrivals
> If the same `seqId` arrives more than once, the implementation ignores later arrivals.
>
> ### Reporting exactly once
> If completed messages should be reported only once, removing the segment after calling `OnComplete` prevents repeated reporting.
>
> ### Complexity
> Let $n$ be the number of received characters.
>
> - Each insertion performs only hash map lookups and at most two merges.
> - Hash operations are $O(1)$ on average.
> - Thus the structural work is $O(1)$ average per character.
>
> If strings are stored by concatenation as above, a merge may copy characters, so the total worst-case string cost can be larger. For interview-style solutions this is usually acceptable. If needed, this can be optimized with linked fragments or ropes.
>
> ---
>
> ## Final Answer
>
> Maintain maximal contiguous received segments keyed by both start and end sequence id. For each incoming character:
>
> 1. create a one-character segment,
> 2. merge with the segment ending at `seqId - 1` if present,
> 3. merge with the segment starting at `seqId + 1` if present,
> 4. if the resulting segment starts and ends with `'-'`, call `OnComplete(segment_string)` immediately.
>
> This correctly prints any full message exactly when it becomes complete.
