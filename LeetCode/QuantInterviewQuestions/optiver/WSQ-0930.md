> [!example] Question 930 · Optiver
> ## Software Engineer Interview

Implement an algorithm to merge N sorted lists.

[Source](https://www.thewallstreetquants.com/ebook#p=931)

> [!success]- Solution (Click to expand)
> ## Solution
>
> To merge $N$ sorted lists efficiently, use a **min-heap** (priority queue). The key idea is to always extract the smallest current element among the heads of all lists, then advance in the list from which that element came.
>
> ### Approach
>
> Suppose there are $N$ sorted lists, and the total number of elements across all lists is $M$.
>
> 1. Initialize a min-heap.
> 2. Insert the first element of each nonempty list into the heap.
>    - Along with the value, store:
>      - the index of the list it came from,
>      - the index of the next element in that list.
> 3. Repeatedly:
>    - Extract the minimum element from the heap,
>    - Append it to the output,
>    - If the extracted element’s list still has more elements, insert the next element from that list into the heap.
> 4. Continue until the heap is empty.
>
> Because the heap contains at most one active element from each list, its size is at most $N$.
>
> ### Correctness
>
> At every step, the heap contains the smallest not-yet-output element from each list that still has remaining elements. Since each list is individually sorted, the minimum among these candidates is the smallest element overall among all remaining elements. Extracting it and then inserting the next element from the same list preserves this invariant. Therefore, the output is globally sorted.
>
> ### Complexity
>
> - Building the initial heap takes $O(N)$ if done in one step, or $O(N \log N)$ with repeated insertion.
> - Each of the $M$ elements is inserted into and removed from the heap exactly once.
> - Each heap operation costs $O(\log N)$.
>
> Thus the total time complexity is
>
> $$
> O(M \log N)
> $$
>
> and the extra space used by the heap is
>
> $$
> O(N).
> $$
>
> ### Pseudocode
>
> ```text
> MERGE_SORTED_LISTS(lists):
>     create empty minHeap
>     result = empty list
>
>     for i = 0 to N - 1:
>         if lists[i] is not empty:
>             push(minHeap, (lists[i][0], i, 0))
>
>     while minHeap is not empty:
>         (value, listIndex, elementIndex) = popMin(minHeap)
>         append value to result
>
>         nextIndex = elementIndex + 1
>         if nextIndex < length(lists[listIndex]):
>             nextValue = lists[listIndex][nextIndex]
>             push(minHeap, (nextValue, listIndex, nextIndex))
>
>     return result
> ```
>
> ### Example
>
> Given
>
> $$
> L_1 = [1, 4, 7], \quad
> L_2 = [2, 5, 8], \quad
> L_3 = [3, 6, 9]
> $$
>
> Initial heap contains
>
> $$
> (1, L_1), \ (2, L_2), \ (3, L_3)
> $$
>
> Extract in order:
>
> $$
> 1, 2, 3, 4, 5, 6, 7, 8, 9
> $$
>
> So the merged result is
>
> $$
> [1, 2, 3, 4, 5, 6, 7, 8, 9].
> $$
>
> ### Final Answer
>
> Use a **min-heap** containing the current smallest unmerged element from each list. Repeatedly remove the minimum and insert the next element from the same list. This merges $N$ sorted lists in
>
> $$
> O(M \log N)
> $$
>
> time with
>
> $$
> O(N)
> $$
>
> extra space, where $M$ is the total number of elements.
