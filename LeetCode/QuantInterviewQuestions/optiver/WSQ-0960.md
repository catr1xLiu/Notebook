> [!example] Question 960 · Optiver
> ## Software Engineer Intern Interview

Given a string representation of a binary tree, write a function to parse the string and construct the tree. Then, identify and return a list of errors found in the tree, such as nodes with more than two children, more than one root, or duplicate parent-child pairs.

> [!success]- Solution (Click to expand)
> ## Giving Tree of Errors
>
> The input is a list of parent-child pairs, and the task is to parse the string, attempt to construct a binary tree from it, and return a list of every structural error found, rather than stopping at the first one encountered.
>
> ### Required Error Checks
>
> The checks called for are:
>
> - more than two children for some node,
> - more than one root,
> - duplicate parent-child pairs.
>
> A complete validator should also confirm that the structure has no cycles and is fully connected, since both are needed for the result to be a single valid tree; these are included below alongside the three required checks.
>
> ### Parsing
>
> The input is usually a string such as
>
> $$
> (A,B)\ (A,C)\ (B,D)
> $$
>
> or a compact equivalent. Each pair represents a directed edge from parent to child.
>
> A parser should:
>
> 1. Split the string into tokens representing pairs.
> 2. Validate each token's format.
> 3. Extract the parent and child characters from each token.
>
> ### Data Structures
>
> Use:
>
> - a set `edges` to detect duplicates,
> - a dictionary `children[u]` storing the child nodes of `u`,
> - a dictionary `indegree[v]` counting how many parents each node has,
> - a set `nodes` of all nodes seen so far,
> - a list `errors` accumulating every problem found.
>
> ### Error Detection Logic
>
> Because the function must report every error rather than the first one, no check causes an early return; each check appends to `errors` and processing continues.
>
> #### Duplicate Pair
>
> Before inserting an edge $(u,v)$, check whether it is already present in the edge set. If so, append a duplicate-pair error for $(u,v)$ and skip re-inserting it, but keep processing the remaining pairs.
>
> #### More Than Two Children
>
> After inserting a child into `children[u]`, check whether
>
> $$
> |children[u]| = 3
> $$
>
> exactly at the moment the third child is added. If so, append a "more than two children" error for $u$. Recording the error only at this transition avoids reporting the same node repeatedly as further children are added.
>
> #### Multiple Roots
>
> After processing all pairs, roots are the nodes with indegree $0$. If there is more than one root, append a multiple-roots error listing them.
>
> If there are no roots at all, every node has at least one parent, which means the edges form one or more cycles; append an error noting that no root exists, since in that case no meaningful tree traversal can begin.
>
> #### Cycle Detection and Connectivity
>
> If at least one root exists, run a depth-first search from each root, marking each node's state as unvisited, in-progress, or done:
>
> - state $0$: unvisited,
> - state $1$: currently being visited (on the recursion stack),
> - state $2$: fully processed.
>
> If the search reaches a node already in state $1$, a cycle has been found; append a cycle error for that node and do not recurse into it again, so the search still terminates.
>
> After the search finishes from every root, any node still in state $0$ was never reached; append a disconnected-nodes error listing them, since a valid single tree must include every node.
>
> ### Binary Tree Construction
>
> If no errors were found, sort each node's children lexicographically and build the standard S-expression form of the tree recursively. If a node has no children:
>
> $$
> (X)
> $$
>
> If it has one child $c$:
>
> $$
> (X\ \text{subtree}(c))
> $$
>
> If it has two children $c_1 < c_2$:
>
> $$
> (X\ \text{subtree}(c_1)\ \text{subtree}(c_2))
> $$
>
> ### Standard Implementation Pattern
>
> ```python
> from collections import defaultdict
>
> def find_tree_errors(s):
>     children = defaultdict(list)
>     indegree = defaultdict(int)
>     edges = set()
>     nodes = set()
>     errors = []
>
>     pairs = parse_pairs(s)
>
>     for u, v in pairs:
>         nodes.add(u)
>         nodes.add(v)
>
>         if (u, v) in edges:
>             errors.append(f"duplicate pair: ({u}, {v})")
>             continue
>
>         edges.add((u, v))
>         children[u].append(v)
>         indegree[v] += 1
>
>         if len(children[u]) == 3:
>             errors.append(f"more than two children: {u}")
>
>     roots = [x for x in nodes if indegree[x] == 0]
>     if len(roots) > 1:
>         errors.append(f"more than one root: {roots}")
>
>     if len(roots) == 0:
>         errors.append("no root found (graph contains a cycle)")
>     else:
>         state = {x: 0 for x in nodes}
>
>         def dfs(u):
>             state[u] = 1
>             for v in children[u]:
>                 if state[v] == 1:
>                     errors.append(f"cycle detected at: {v}")
>                 elif state[v] == 0:
>                     dfs(v)
>             state[u] = 2
>
>         for r in roots:
>             if state[r] == 0:
>                 dfs(r)
>
>         unreached = [x for x in nodes if state[x] == 0]
>         if unreached:
>             errors.append(f"disconnected nodes: {unreached}")
>
>     return errors
>
> def build_tree(root, children):
>     for u in children:
>         children[u].sort()
>
>     def build(u):
>         result = f"({u}"
>         for v in children[u]:
>             result += build(v)
>         result += ")"
>         return result
>
>     return build(root)
> ```
>
> The caller first invokes `find_tree_errors`; if the returned list is empty, the pairs describe a valid binary tree, and `build_tree` can be used to produce its S-expression form.
>
> ### Important Edge Cases
>
> A robust solution should also consider:
>
> 1. A child with two different parents violates the definition of a tree; this is already caught indirectly, since the second parent's edge either creates a second component or a cycle, but it can also be flagged directly by checking $\text{indegree}[v] > 1$ and appending a dedicated error.
> 2. A disconnected graph with one rooted component and a separate cycle elsewhere; the connectivity check after the depth-first search catches this.
> 3. Multiple roots caused by isolated parent-child groups; counting indegree-$0$ nodes catches this.
> 4. Duplicate input hidden by ordering or spacing; the parser should normalize tokens before comparing them.
> 5. A node whose children were inserted out of sorted order; children are sorted before the S-expression is produced.
>
> ### Final Summary
>
> The Giving Tree of Errors problem requires validating the full graph structure and reporting every issue found, rather than the first one:
>
> - detect duplicate pairs,
> - flag any node with more than two children,
> - flag more than one root, or no root at all,
> - detect cycles,
> - verify that every node is reachable from the root,
> - if the list of errors is empty, build the tree in sorted S-expression form.
>
> Because the input may hide multiple simultaneous problems, a correct solution must accumulate all applicable errors into a list rather than stopping at the first one it encounters.
