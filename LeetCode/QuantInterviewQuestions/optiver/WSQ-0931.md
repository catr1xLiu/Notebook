> [!example] Question 931 · Optiver
> ## Developer Interview

Why are the wait and notify methods declared in the Object class instead of the Thread class in Java?

[Source](https://www.thewallstreetquants.com/ebook#p=932)

> [!success]- Solution (Click to expand)
> `wait()`, `notify()`, and `notifyAll()` are declared in `Object` because they are tied to an object's **monitor**, not to a thread itself.
>
> ## 1. Every object has an intrinsic lock
>
> In Java, each object can act as a monitor. That means any object can be used in synchronization:
>
> ```java
> synchronized (someObject) {
>     ...
> }
> ```
>
> When a thread enters such a block, it acquires the monitor associated with `someObject`.
>
> Since waiting and notification happen with respect to that monitor, the methods must belong to the object whose monitor is being used.
>
> ## 2. `wait()` means “release this object's monitor and sleep”
>
> If a thread executes
>
> ```java
> synchronized (someObject) {
>     someObject.wait();
> }
> ```
>
> the meaning is:
>
> - the current thread releases the monitor of `someObject`,
> - it enters the waiting set associated with `someObject`,
> - it remains blocked until another thread calls `notify()` or `notifyAll()` on `someObject`.
>
> Thus, `wait()` is not an operation on the thread in isolation; it is an operation on the monitor of a particular object.
>
> ## 3. `notify()` means “wake a thread waiting on this object's monitor”
>
> Similarly,
>
> ```java
> synchronized (someObject) {
>     someObject.notify();
> }
> ```
>
> means:
>
> - choose one thread waiting on `someObject`'s monitor,
> - move it from the waiting state to a runnable/blocked-to-reacquire-lock state.
>
> Again, the notification is associated with a specific object, not with a specific thread.
>
> ## 4. Why not put them in `Thread`?
>
> If these methods were in `Thread`, the model would be wrong:
>
> - a thread can wait on many different objects,
> - synchronization is done on objects, not on thread instances,
> - the question is not “which thread should wait?” but rather “on which object's monitor should the thread wait?”
>
> For example, in
>
> ```java
> synchronized (queue) {
>     while (queue.isEmpty()) {
>         queue.wait();
>     }
> }
> ```
>
> the waiting condition is about `queue`. The monitor and wait set belong to `queue`, so `queue.wait()` is the natural and correct design.
>
> ## 5. Enforcement of monitor ownership
>
> Java requires that the current thread must own the object's monitor before calling `wait()`, `notify()`, or `notifyAll()`. Otherwise, it throws `IllegalMonitorStateException`.
>
> This requirement further shows that these methods are monitor-related object operations, not ordinary thread operations.
>
> ## Conclusion
>
> `wait()`, `notify()`, and `notifyAll()` are in `Object` because they operate on an object's intrinsic monitor:
>
> - every object has a monitor,
> - threads synchronize on objects,
> - waiting and notification are defined relative to a particular object's monitor.
>
> Therefore, they belong to `Object`, not to `Thread`.
