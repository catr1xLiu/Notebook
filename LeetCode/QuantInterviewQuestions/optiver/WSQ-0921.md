> [!example] Question 921 · Optiver
> ## Software Engineer Interview

Given an array of stock prices for n days, return the maximum profit achievable using at most k transactions. Complete the function int stock(int\* prices, int k, int n).

[Source](https://www.thewallstreetquants.com/ebook#p=922)

> [!success]- Solution (Click to expand)
> ## Solution
>
> A transaction consists of one **buy** followed later by one **sell**. At most $k$ such transactions are allowed, and no overlapping transactions are permitted.
>
> The standard dynamic programming formulation is:
>
> - Let $dp[t][i]$ be the maximum profit obtainable using at most $t$ transactions during the first $i+1$ days, that is, from day $0$ to day $i$.
> - For each transaction count $t$, and each day $i$, either:
>   1. we do not sell on day $i$, so profit remains $dp[t][i-1]$, or
>   2. we sell on day $i$, having bought on some earlier day $j$, giving profit
>      $$
>      prices[i] - prices[j] + dp[t-1][j-1].
>      $$
>
> Thus,
> $$
> dp[t][i] = \max\left(dp[t][i-1], \max_{0 \le j < i}\left(prices[i] - prices[j] + dp[t-1][j-1]\right)\right).
> $$
>
> A direct implementation would be $O(kn^2)$, but this can be optimized to $O(kn)$ by maintaining
> $$
> best = \max_{0 \le j < i}\left(dp[t-1][j-1] - prices[j]\right).
> $$
>
> Then,
> $$
> dp[t][i] = \max\left(dp[t][i-1], prices[i] + best\right).
> $$
>
> Since only the previous transaction layer is needed, the space can be reduced to $O(n)$.
>
> ---
>
> ## Special case
>
> If $k \ge \left\lfloor \frac{n}{2} \right\rfloor$, then the transaction limit is effectively irrelevant, because one can complete as many profitable rising segments as possible. In that case, the answer is simply:
> $$
> \sum_{i=1}^{n-1} \max(0, prices[i] - prices[i-1]).
> $$
>
> ---
>
> ## Implementation
>
> ```c
> int stock(int* prices, int k, int n) {
>     if (n <= 1 || k == 0) return 0;
>
>     if (k >= n / 2) {
>         int profit = 0;
>         for (int i = 1; i < n; i++) {
>             if (prices[i] > prices[i - 1]) {
>                 profit += prices[i] - prices[i - 1];
>             }
>         }
>         return profit;
>     }
>
>     int prev[n];
>     int curr[n];
>
>     for (int i = 0; i < n; i++) prev[i] = 0;
>
>     for (int t = 1; t <= k; t++) {
>         curr[0] = 0;
>         int best = -prices[0];
>
>         for (int i = 1; i < n; i++) {
>             int candidate = prices[i] + best;
>             curr[i] = (curr[i - 1] > candidate) ? curr[i - 1] : candidate;
>
>             int value = prev[i - 1] - prices[i];
>             if (value > best) best = value;
>         }
>
>         for (int i = 0; i < n; i++) prev[i] = curr[i];
>     }
>
>     return prev[n - 1];
> }
> ```
>
> ---
>
> ## Correctness
>
> For each transaction count $t$ and day $i$:
>
> - $curr[i-1]$ represents the best profit using at most $t$ transactions up to day $i-1$, so it covers the case of not selling on day $i$.
> - $prices[i] + best$ represents the best profit obtained by completing the $t$-th transaction on day $i$, where
>   $$
>   best = \max_{0 \le j < i}\left(prev[j-1] - prices[j]\right),
>   $$
>   with the case $j=0$ handled as $-prices[0]$.
>
> Taking the maximum of these two choices gives the optimal value for $curr[i]$. Repeating this for all $i$ and $t$ yields the maximum profit with at most $k$ transactions.
>
> ---
>
> ## Complexity
>
> - Time complexity: $O(kn)$
> - Space complexity: $O(n)$
>
> ---
>
> ## Final Answer
>
> The maximum profit within at most $k$ transactions can be computed in $O(kn)$ time and $O(n)$ space using dynamic programming, with the implementation shown above.
