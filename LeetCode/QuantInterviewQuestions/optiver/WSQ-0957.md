> ## Implementing a Queue
>
> A queue is a linear data structure that follows the **FIFO** principle: **first in, first out**. The basic operations are:
>
> - **enqueue**: insert an element at the rear
> - **dequeue**: remove an element from the front
> - **front/peek**: inspect the front element
> - **isEmpty**: check whether the queue has no elements
>
> There are several common ways to implement a queue.
>
> ### 1. Linked-list implementation
> Maintain:
> - a pointer to the **head** (front),
> - a pointer to the **tail** (rear).
>
> Then:
> - **enqueue** adds a node at the tail in $O(1)$ time,
> - **dequeue** removes the node at the head in $O(1)$ time.
>
> This is a standard dynamic-size implementation.
>
> ### 2. Array implementation
> Using a plain array, one may store elements in order and keep indices for the front and rear. However, if one simply increments indices, space at the beginning of the array becomes unused after dequeues. The correct array-based solution is therefore a **circular queue**.
>
> ---
>
> ## Array-Based Queue: Circular Buffer
>
> ### Idea
> Use:
> - an array `data` of fixed capacity,
> - an index `front` pointing to the current front element,
> - an index `size` for the number of elements.
>
> The rear position is computed by
>
> $$
> \text{rear} = (\text{front} + \text{size}) \bmod \text{capacity}.
> $$
>
> This avoids shifting elements and makes both enqueue and dequeue run in $O(1)$ time.
>
> ---
>
> ## Operations
>
> Assume:
> - `data` has length `capacity`,
> - `front` is the index of the first element,
> - `size` is the number of elements.
>
> ### Enqueue
> To insert `x`:
> 1. If `size == capacity`, the queue is full.
> 2. Compute insertion index:
>
> $$
> (\text{front} + \text{size}) \bmod \text{capacity}
> $$
>
> 3. Store `x` there.
> 4. Increment `size`.
>
> ### Dequeue
> To remove the front element:
> 1. If `size == 0`, the queue is empty.
> 2. Read `data[front]`.
> 3. Advance `front`:
>
> $$
> \text{front} = (\text{front} + 1) \bmod \text{capacity}
> $$
>
> 4. Decrement `size`.
>
> ### Peek
> Return `data[front]` if the queue is nonempty.
>
> ---
>
> ## Java Implementation
>
> ```java
> public class ArrayQueue<T> {
>     private T[] data;
>     private int front;
>     private int size;
>
>     @SuppressWarnings("unchecked")
>     public ArrayQueue(int capacity) {
>         data = (T[]) new Object[capacity];
>         front = 0;
>         size = 0;
>     }
>
>     public boolean isEmpty() {
>         return size == 0;
>     }
>
>     public boolean isFull() {
>         return size == data.length;
>     }
>
>     public int size() {
>         return size;
>     }
>
>     public void enqueue(T value) {
>         if (isFull()) {
>             throw new RuntimeException("Queue is full");
>         }
>         int rear = (front + size) % data.length;
>         data[rear] = value;
>         size++;
>     }
>
>     public T dequeue() {
>         if (isEmpty()) {
>             throw new RuntimeException("Queue is empty");
>         }
>         T value = data[front];
>         data[front] = null; // optional: helps garbage collection
>         front = (front + 1) % data.length;
>         size--;
>         return value;
>     }
>
>     public T peek() {
>         if (isEmpty()) {
>             throw new RuntimeException("Queue is empty");
>         }
>         return data[front];
>     }
> }
> ```
>
> ---
>
> ## Example
>
> Suppose the capacity is $5$.
>
> Start with:
> - `front = 0`
> - `size = 0`
>
> After `enqueue(10), enqueue(20), enqueue(30)`:
>
> - array: `[10, 20, 30, _, _]`
> - `front = 0`
> - `size = 3`
>
> After `dequeue()`:
>
> - returned value: `10`
> - `front = 1`
> - `size = 2`
>
> After `enqueue(40), enqueue(50), enqueue(60)`:
>
> Insertions wrap around using modulo arithmetic, so the array may become:
>
> - array: `[60, 20, 30, 40, 50]`
> - `front = 1`
> - `size = 5`
>
> The logical queue order is still:
>
> $$
> 20, 30, 40, 50, 60
> $$
>
> even though the physical array is wrapped.
>
> ---
>
> ## Complexity
>
> For the circular-array queue:
>
> - `enqueue`: $O(1)$
> - `dequeue`: $O(1)$
> - `peek`: $O(1)$
> - space: $O(n)$
>
> ---
>
> ## Final Answer
>
> A queue can be implemented either with a linked list or with an array. For an array-based queue, the correct efficient design is a **circular buffer**, storing:
> - the array,
> - a `front` index,
> - a `size` counter.
>
> Then:
> - enqueue at index $$(\text{front} + \text{size}) \bmod \text{capacity}$$
> - dequeue from `front`, then update $$\text{front} = (\text{front} + 1) \bmod \text{capacity}$$
>
> This gives $O(1)$ time for both insertion and removal without shifting elements.
