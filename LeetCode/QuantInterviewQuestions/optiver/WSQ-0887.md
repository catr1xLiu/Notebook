> [!example] Question 887 · Optiver
> ## Software Engineer Interview

Complete a function that takes in a seqId (int) and a char (consisting of 'a'-'z' and '-'). The seqId values may be received out of order. A full message is formed when the characters, sorted by seqId, create a string in the format "-FullMessage-". The goal is to print out any full message exactly when it completes, using the provided OnComplete(msg) function.

> ## Solution
>
> Maintain the set of received characters indexed by `seqId`, and detect completion only when a newly received character causes some contiguous interval to become a complete message of the form `"-...-"`.
>
> A message is complete exactly when there exist indices $L < R$ such that:
>
> - the characters at $L$ and $R$ are `'-'`,
> - every index in $[L,R]$ has been received,
> - there is no missing index inside that interval.
>
> Then the message content is the concatenation of characters from $L$ through $R$.
>
> ### Data structure
>
> Use:
>
> - a hash map `chars` from `seqId` to character,
> - a disjoint-set-style interval map to track maximal contiguous received ranges.
>
> For simplicity, store intervals by their endpoints:
>
> - `startToEnd[s] = e` means there is a fully received interval $[s,e]$,
> - `endToStart[e] = s`.
>
> When a new character at position $x$ arrives, it may connect with an interval ending at $x-1$, an interval starting at $x+1$, both, or neither.
>
> This lets us merge intervals in $O(1)$ expected time.
>
> After merging, suppose the resulting complete interval is $[s,e]$. A newly completed message can only be one whose endpoints are both inside this interval and whose final missing character was just inserted. Since only the new character can change completeness, it suffices to check whether the whole merged interval itself forms a message; if later a larger interval forms, that larger one will be checked when completed.
>
> Thus, after each insertion, if:
>
> - `chars[s] == '-'`,
> - `chars[e] == '-'`,
> - and $s < e$,
>
> then the string from $s$ to $e$ is a complete message and should be emitted.
>
> To avoid duplicate emission, keep a set of emitted endpoint pairs.
>
> ### Correctness argument
>
> When a character at index $x$ is inserted, all previously complete intervals remain unchanged; only intervals containing $x$ can become newly complete. The merge logic constructs exactly the maximal contiguous received interval containing $x$. If that interval has `'-'` at both endpoints, then every position between them has been received, so it is exactly a complete message of the required form `"-FullMessage-"`. Conversely, any newly completed message must contain $x$, hence lies inside the merged interval; when its two endpoint dashes are both present and all interior positions are present, it is complete at that moment. Emitting each completed dash-bounded contiguous interval once is therefore correct.
>
> ### Implementation
>
> ```cpp
> #include <unordered_map>
> #include <unordered_set>
> #include <string>
> using namespace std;
>
> // Provided externally.
> void OnComplete(const string& msg);
>
> class MessageAssembler {
> private:
>     unordered_map<int, char> chars;
>
>     // Interval maps for maximal contiguous received ranges.
>     unordered_map<int, int> startToEnd;
>     unordered_map<int, int> endToStart;
>
>     // Avoid duplicate prints.
>     unordered_set<long long> emitted;
>
>     long long key(int s, int e) {
>         return (static_cast<long long>(s) << 32) ^ static_cast<unsigned int>(e);
>     }
>
>     void tryEmit(int s, int e) {
>         if (s >= e) return;
>         if (!chars.count(s) || !chars.count(e)) return;
>         if (chars[s] != '-' || chars[e] != '-') return;
>
>         long long k = key(s, e);
>         if (emitted.count(k)) return;
>
>         string msg;
>         msg.reserve(e - s + 1);
>         for (int i = s; i <= e; ++i) {
>             msg.push_back(chars[i]);
>         }
>
>         emitted.insert(k);
>         OnComplete(msg);
>     }
>
> public:
>     void Add(int seqId, char c) {
>         if (chars.count(seqId)) return; // Ignore duplicates if any.
>
>         chars[seqId] = c;
>
>         bool hasLeft = endToStart.count(seqId - 1);
>         bool hasRight = startToEnd.count(seqId + 1);
>
>         int s = seqId, e = seqId;
>
>         if (hasLeft && hasRight) {
>             int leftStart = endToStart[seqId - 1];
>             int rightEnd = startToEnd[seqId + 1];
>
>             // Remove old intervals.
>             endToStart.erase(seqId - 1);
>             startToEnd.erase(seqId + 1);
>             startToEnd.erase(leftStart);
>             endToStart.erase(rightEnd);
>
>             s = leftStart;
>             e = rightEnd;
>         } else if (hasLeft) {
>             int leftStart = endToStart[seqId - 1];
>
>             endToStart.erase(seqId - 1);
>             startToEnd.erase(leftStart);
>
>             s = leftStart;
>             e = seqId;
>         } else if (hasRight) {
>             int rightEnd = startToEnd[seqId + 1];
>
>             startToEnd.erase(seqId + 1);
>             endToStart.erase(rightEnd);
>
>             s = seqId;
>             e = rightEnd;
>         }
>
>         startToEnd[s] = e;
>         endToStart[e] = s;
>
>         tryEmit(s, e);
>     }
> };
> ```
>
> ### Example
>
> Suppose characters arrive in this order:
>
> - $(2, 'e')$
> - $(1, 'h')$
> - $(0, '-')$
> - $(4, '-')$
> - $(3, 'y')$
>
> After the final insertion, the contiguous interval $[0,4]$ is complete and equals `"-hey-"`, so `OnComplete("-hey-")` is called.
>
> ### Complexity
>
> Each insertion performs only hash-map operations and at most one linear scan when emitting a completed message.
>
> - Update time: $O(1)$ expected, excluding output construction.
> - Emission time: $O(L)$ for a message of length $L$.
> - Space: $O(n)$ for $n$ received characters.
