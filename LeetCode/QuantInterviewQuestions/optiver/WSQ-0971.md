> [!example] Question 971 · Optiver
> ## Senior Software Engineer Interview

Given a graph and two vertices, implement Dijkstra's algorithm to find the shortest distance between the pair. Additionally, return an error if there are multiple shortest paths with the same distance between the vertices.

[Source](https://www.thewallstreetquants.com/ebook#p=972)

> [!success]- Solution (Click to expand)
> ## Dijkstra-style shortest path with ambiguity detection
>
> ### Problem interpretation
>
> Given a weighted graph and two specified vertices $s$ and $t$, compute the shortest-path distance from $s$ to $t$ using Dijkstra's algorithm, under the additional requirement:
>
> - if there is **more than one distinct shortest path** from $s$ to $t$, return an **error** instead of a distance.
>
> This condition means it is not enough to know the minimum distance; one must also determine whether that minimum is achieved uniquely.
>
> ---
>
> ### Key idea
>
> Standard Dijkstra's algorithm computes the minimum distance from $s$ to every vertex when all edge weights are nonnegative. To detect whether the shortest path is unique, maintain for each vertex:
>
> - $\text{dist}[v]$: the currently known shortest distance from $s$ to $v$,
> - $\text{count}[v]$: the number of shortest paths from $s$ to $v$.
>
> The algorithm updates these values as follows.
>
> For an edge $(u,v)$ with weight $w$:
>
> 1. If a strictly shorter path is found:
>    $$
>    \text{dist}[u] + w < \text{dist}[v],
>    $$
>    then set
>    $$
>    \text{dist}[v] = \text{dist}[u] + w,
>    \qquad
>    \text{count}[v] = \text{count}[u].
>    $$
>
> 2. If another path with the same shortest length is found:
>    $$
>    \text{dist}[u] + w = \text{dist}[v],
>    $$
>    then add the number of shortest paths through $u$:
>    $$
>    \text{count}[v] \leftarrow \text{count}[v] + \text{count}[u].
>    $$
>
> At the end:
>
> - if $\text{dist}[t] = \infty$, then $t$ is unreachable,
> - if $\text{count}[t] = 1$, return $\text{dist}[t]$,
> - if $\text{count}[t] > 1$, return an error indicating multiple shortest paths.
>
> ---
>
> ### Algorithm
>
> Assume the graph is represented as an adjacency list, and all edge weights are nonnegative.
>
> #### Initialization
>
> For every vertex $v$:
>
> $$
> \text{dist}[v] = \infty, \qquad \text{count}[v] = 0.
> $$
>
> Set
>
> $$
> \text{dist}[s] = 0, \qquad \text{count}[s] = 1.
> $$
>
> Insert $(0,s)$ into a min-priority queue.
>
> ---
>
> ### Pseudocode
>
> ```text
> DijkstraUniqueShortestPath(Graph, s, t):
>     for each vertex v in Graph:
>         dist[v] = infinity
>         count[v] = 0
>
>     dist[s] = 0
>     count[s] = 1
>
>     priority queue pq
>     pq.push((0, s))
>
>     while pq is not empty:
>         (du, u) = pq.pop()
>
>         if du > dist[u]:
>             continue
>
>         for each edge (u, v, w) outgoing from u:
>             newDist = dist[u] + w
>
>             if newDist < dist[v]:
>                 dist[v] = newDist
>                 count[v] = count[u]
>                 pq.push((dist[v], v))
>
>             else if newDist == dist[v]:
>                 count[v] = count[v] + count[u]
>
>     if dist[t] == infinity:
>         return "error: no path exists"
>
>     if count[t] > 1:
>         return "error: multiple shortest paths"
>
>     return dist[t]
> ```
>
> ---
>
> ### Correctness argument
>
> The correctness follows from two facts.
>
> #### 1. Distance correctness
>
> Because all edge weights are nonnegative, Dijkstra's algorithm correctly computes
>
> $$
> \text{dist}[v] = \delta(s,v),
> $$
>
> where $\delta(s,v)$ is the true shortest-path distance from $s$ to $v$.
>
> #### 2. Path-count correctness
>
> Proceed by induction over the order in which vertices are finalized by Dijkstra's algorithm.
>
> - Initially, for the source $s$, there is exactly one shortest path of length $0$, namely the trivial path, so
>   $$
>   \text{count}[s] = 1.
>   $$
>
> - Suppose for all previously finalized vertices, $\text{count}$ equals the number of shortest paths from $s$.
>   When relaxing an edge $(u,v)$:
>   - if a strictly shorter path to $v$ is found, then every previously known path to $v$ is irrelevant, so the number of shortest paths to $v$ becomes exactly the number of shortest paths to $u$;
>   - if an equally short path is found, then this contributes additional shortest paths, so the counts are added.
>
> Thus, after all relaxations, $\text{count}[v]$ equals the total number of shortest paths from $s$ to $v$.
>
> Therefore:
> - $\text{count}[t] = 1$ means the shortest path is unique,
> - $\text{count}[t] > 1$ means multiple shortest paths exist.
>
> Hence the algorithm returns exactly the required result.
>
> ---
>
> ### Time complexity
>
> Using a binary heap priority queue:
>
> - each edge relaxation is processed in $O(1)$ time, aside from heap operations,
> - each heap insertion or extraction costs $O(\log |V|)$.
>
> Thus the total running time is
>
> $$
> O\big((|V| + |E|)\log |V|\big),
> $$
>
> which is the standard complexity of Dijkstra's algorithm.
>
> The extra storage for the $\text{count}$ array is
>
> $$
> O(|V|).
> $$
>
> ---
>
> ### Important note
>
> This method requires **nonnegative edge weights**. If negative-weight edges are allowed, Dijkstra's algorithm is not correct; one would need a different algorithm such as Bellman-Ford, together with analogous path-count tracking.
>
> ---
>
> ## Final answer
>
> To solve the problem, use Dijkstra's algorithm augmented with a path-count array:
>
> - maintain $\text{dist}[v]$ for shortest distance,
> - maintain $\text{count}[v]$ for the number of shortest paths.
>
> At the end:
>
> - if $\text{dist}[t] = \infty$, return an error for no path,
> - if $\text{count}[t] > 1$, return an error for multiple shortest distances,
> - otherwise return $\text{dist}[t]$.
>
> This runs in
>
> $$
> O\big((|V| + |E|)\log |V|\big)
> $$
>
> time for graphs with nonnegative edge weights.
