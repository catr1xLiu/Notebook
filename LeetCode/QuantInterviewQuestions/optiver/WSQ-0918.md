> [!example] Question 918 · Optiver
> ## Software Engineer Interview

How much memory is required to store a linked list with 1,000 elements?

[Source](https://www.thewallstreetquants.com/ebook#p=919)

> [!success]- Solution (Click to expand)
> To estimate the memory required for a linked list with $1000$ elements, account for two parts in each node:
>
> 1. the data stored in the node,
> 2. the pointer to the next node.
>
> Thus, if each node stores:
>
> - data of size $d$ bytes,
> - one pointer of size $p$ bytes,
>
> then the total memory is
>
> $$
> 1000(d+p)\ \text{bytes}.
> $$
>
> ### Common cases
>
> #### Case 1: Integer data, $32$-bit system
> If each node stores an integer of $4$ bytes and a pointer of $4$ bytes, then each node uses
>
> $$
> 4+4=8\ \text{bytes}.
> $$
>
> So the total memory is
>
> $$
> 1000 \times 8 = 8000\ \text{bytes}.
> $$
>
> #### Case 2: Integer data, $64$-bit system
> If each node stores an integer of $4$ bytes and a pointer of $8$ bytes, then each node uses
>
> $$
> 4+8=12\ \text{bytes}.
> $$
>
> So the total memory is
>
> $$
> 1000 \times 12 = 12000\ \text{bytes}.
> $$
>
> ### Note on actual memory usage
> In practice, the real amount may be slightly larger because of:
>
> - padding for memory alignment,
> - allocator overhead,
> - possible metadata stored by the language runtime.
>
> ### Final answer
> For a linked list of $1000$ elements,
>
> $$
> \text{Memory} = 1000 \times (\text{data size} + \text{pointer size}).
> $$
>
> For example, with integer data:
>
> - on a $32$-bit system: $8000$ bytes,
> - on a $64$-bit system: about $12000$ bytes, often rounded higher in practice due to overhead.
