> [!example] Question 454 · Jane Street
> ## Quantitative Trader Interview

You are given an array of k linked lists, each of which is sorted in ascending order. Merge all the linked lists into one sorted linked list and return it.

[Source](https://www.thewallstreetquants.com/ebook#p=455)

> [!success]- Solution (Click to expand)
> ## Approach
>
> Each of the $k$ linked lists is already sorted. To produce one globally sorted list efficiently, always take the smallest current node among the heads of the nonempty lists.
>
> A min-heap (priority queue) supports this operation well:
>
> - Insert the head of each nonempty list into the heap.
> - Repeatedly extract the smallest node from the heap.
> - Append it to the answer list.
> - If the extracted node has a next node, insert that next node into the heap.
>
> At every step, the heap contains the smallest remaining candidate from each list, so the extracted node is always the next node in sorted order.
>
> ## Algorithm
>
> 1. Create a min-heap.
> 2. Push the head of every nonempty list into the heap.
> 3. Use a dummy node to simplify construction of the result list.
> 4. While the heap is not empty:
>    - Pop the smallest node.
>    - Attach it to the result.
>    - If it has a successor, push that successor into the heap.
> 5. Return `dummy.next`.
>
> ## Correctness
>
> Let the heap contain exactly the first unmerged node from each list that still has remaining nodes.
>
> Because each list is sorted, the first unmerged node of a list is the smallest remaining node from that list. Therefore, the minimum element in the heap is the smallest among all nodes not yet placed in the output.
>
> When that minimum node is removed and appended to the result, the next node from the same list becomes that list’s first unmerged node, so inserting it preserves the heap invariant.
>
> By repeating this process until the heap is empty, nodes are appended in nondecreasing order, and every node is included exactly once. Hence the resulting linked list is the correct merged sorted list.
>
> ## Complexity
>
> Suppose the total number of nodes across all lists is $N$, and there are $k$ lists.
>
> - Each node is inserted into and removed from the heap once.
> - Each heap operation costs $O(\log k)$.
>
> Thus the total time complexity is
>
> $$
> O(N \log k).
> $$
>
> The heap stores at most one active node from each list, so the extra space is
>
> $$
> O(k).
> $$
>
> ## Python Implementation
>
> ```python
> from typing import List, Optional
> import heapq
>
> # Definition for singly-linked list.
> # class ListNode:
> #     def __init__(self, val=0, next=None):
> #         self.val = val
> #         self.next = next
>
> class Solution:
>     def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
>         heap = []
>         
>         for i, node in enumerate(lists):
>             if node:
>                 heapq.heappush(heap, (node.val, i, node))
>         
>         dummy = ListNode(0)
>         tail = dummy
>         
>         while heap:
>             _, i, node = heapq.heappop(heap)
>             tail.next = node
>             tail = tail.next
>             
>             if node.next:
>                 heapq.heappush(heap, (node.next.val, i, node.next))
>         
>         tail.next = None
>         return dummy.next
> ```
>
> ## Final Answer
>
> Use a min-heap to repeatedly choose the smallest head among the $k$ lists, append it to the merged list, and push its successor into the heap. This yields a correct merged sorted list in
>
> $$
> O(N \log k)
> $$
>
> time and
>
> $$
> O(k)
> $$
>
> extra space, where $N$ is the total number of nodes.
