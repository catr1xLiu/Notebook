> [!example] Question 244 · Jane Street
> ## Quantitative Analyst Interview

Design a heap data structure that supports adding elements and removing the top element, with the following constraints: (1) The topmost element must always be less than the topmost element in the left and right child subtrees; (2) The left child subtree must have as many or one more element than the right child subtree. The heap should also support a 'min' function (returns the value at the top of the tree) and an 'empty' function (returns an empty tree). Provide a description and implementation of such a data structure.

[Source](https://www.thewallstreetquants.com/ebook#p=245)

> [!success]- Solution (Click to expand)
> ## Heap design and implementation in OCaml
>
> The required structure is a **min-heap** with the following invariants:
>
> 1. The root contains the minimum element.
> 2. Every element in the left and right subtrees is greater than or equal to the root.
> 3. The left subtree has either the same number of elements as the right subtree, or exactly one more.
>
> This is naturally implemented as a **left-complete binary heap**.
>
> ---
>
> ## Representation
>
> A convenient representation stores, at each node, the size of the subtree together with the root value and the two children:
>
> ```ocaml
> type 'a heap =
>   | Empty
>   | Node of int * 'a * 'a heap * 'a heap
> ```
>
> Here:
>
> - `Empty` is the empty heap,
> - `Node (n, x, l, r)` represents a heap of size `n`, root value `x`, left subtree `l`, and right subtree `r`.
>
> ---
>
> ## Basic operations
>
> ### Size
>
> ```ocaml
> let size = function
>   | Empty -> 0
>   | Node (n, _, _, _) -> n
> ```
>
> ### Empty heap
>
> ```ocaml
> let empty = Empty
> ```
>
> ### Minimum element
>
> Since this is a min-heap, the minimum is always at the root:
>
> ```ocaml
> let min = function
>   | Empty -> failwith "empty heap"
>   | Node (_, x, _, _) -> x
> ```
>
> ---
>
> ## Insertion
>
> To insert an element while preserving the shape condition, place the new element into the subtree that currently has fewer elements. Since the left subtree must always have at least as many elements as the right subtree, insertion proceeds as follows:
>
> - if the two subtrees have equal size, insert into the left subtree;
> - otherwise insert into the right subtree.
>
> After insertion, restore the heap-order property by swapping values if necessary.
>
> ```ocaml
> let rec insert x = function
>   | Empty -> Node (1, x, Empty, Empty)
>   | Node (n, y, l, r) ->
>       if size l = size r then
>         let l' = insert x l in
>         begin
>           match l' with
>           | Empty -> assert false
>           | Node (_, ly, _, _) ->
>               if ly < y then
>                 Node (n + 1, ly, Node (size l' , y,
>                                        (match l' with Node (_, _, ll, lr) -> ll | _ -> Empty),
>                                        (match l' with Node (_, _, ll, lr) -> lr | _ -> Empty)), r)
>               else
>                 Node (n + 1, y, l', r)
>         end
>       else
>         let r' = insert x r in
>         begin
>           match r' with
>           | Empty -> assert false
>           | Node (_, ry, _, _) ->
>               if ry < y then
>                 Node (n + 1, ry, l,
>                       Node (size r', y,
>                             (match r' with Node (_, _, rl, rr) -> rl | _ -> Empty),
>                             (match r' with Node (_, _, rl, rr) -> rr | _ -> Empty)))
>               else
>                 Node (n + 1, y, l, r')
>         end
> ```
>
> This version works, but it is unnecessarily awkward because it repeatedly deconstructs subtrees. A cleaner formulation uses a helper to rebuild nodes.
>
> ---
>
> ## Cleaner insertion
>
> ```ocaml
> type 'a heap =
>   | Empty
>   | Node of int * 'a * 'a heap * 'a heap
>
> let size = function
>   | Empty -> 0
>   | Node (n, _, _, _) -> n
>
> let empty = Empty
>
> let min = function
>   | Empty -> failwith "empty heap"
>   | Node (_, x, _, _) -> x
>
> let make_node x l r =
>   Node (1 + size l + size r, x, l, r)
>
> let rec insert x = function
>   | Empty -> make_node x Empty Empty
>   | Node (_, y, l, r) ->
>       if size l = size r then
>         let l' = insert x l in
>         begin
>           match l' with
>           | Empty -> assert false
>           | Node (_, z, ll, lr) ->
>               if z < y then
>                 make_node z (make_node y ll lr) r
>               else
>                 make_node y l' r
>         end
>       else
>         let r' = insert x r in
>         begin
>           match r' with
>           | Empty -> assert false
>           | Node (_, z, rl, rr) ->
>               if z < y then
>                 make_node z l (make_node y rl rr)
>               else
>                 make_node y l r'
>         end
> ```
>
> This preserves both:
>
> - the **shape invariant** by inserting into the appropriate subtree,
> - the **heap invariant** by bubbling the smaller value upward.
>
> ---
>
> ## Removing the minimum
>
> Removing the top element is more subtle. A standard method is:
>
> 1. Remove the **last element** in level-order, so that the shape invariant remains valid.
> 2. Move that last element to the root.
> 3. Percolate it downward until the heap-order property is restored.
>
> Thus, two helpers are needed:
>
> - one to remove the last element,
> - one to push a root value downward.
>
> ---
>
> ## Removing the last element
>
> Because the tree is left-complete, the last element lies:
>
> - in the right subtree if the left subtree has one more element than the right,
> - otherwise in the left subtree.
>
> ```ocaml
> let rec remove_last = function
>   | Empty -> failwith "empty heap"
>   | Node (_, x, Empty, Empty) -> (x, Empty)
>   | Node (_, x, l, r) ->
>       if size l = size r then
>         let (last, l') = remove_last l in
>         (last, make_node x l' r)
>       else
>         let (last, r') = remove_last r in
>         (last, make_node x l r')
> ```
>
> ---
>
> ## Restoring heap order downward
>
> Given a root value and two heaps that already satisfy the heap invariant, place the root value in the correct position.
>
> ```ocaml
> let rec sift_down x l r =
>   match (l, r) with
>   | (Empty, Empty) -> make_node x Empty Empty
>   | (Node (_, lx, ll, lr), Empty) ->
>       if x <= lx then
>         make_node x l Empty
>       else
>         make_node lx (sift_down x ll lr) Empty
>   | (Node (_, lx, ll, lr), Node (_, rx, rl, rr)) ->
>       if x <= lx && x <= rx then
>         make_node x l r
>       else if lx <= rx then
>         make_node lx (sift_down x ll lr) r
>       else
>         make_node rx l (sift_down x rl rr)
>   | (Empty, _) -> failwith "invalid heap shape"
> ```
>
> The case `(Empty, _)` cannot occur in a valid heap, because the left subtree must never have fewer elements than the right subtree.
>
> ---
>
> ## Delete minimum
>
> Now the root can be removed as follows:
>
> ```ocaml
> let delete_min = function
>   | Empty -> failwith "empty heap"
>   | Node (_, _, Empty, Empty) -> Empty
>   | h ->
>       let (last, h_without_last) = remove_last h in
>       match h_without_last with
>       | Empty -> Empty
>       | Node (_, _, l, r) -> sift_down last l r
> ```
>
> ---
>

> ## Correctness
>
> ### Heap-order property
>
> - `insert` preserves heap order by recursively inserting into a valid subtree and then swapping the inserted value upward when necessary.
> - `delete_min` replaces the root by the last element and uses `sift_down` to move that element downward until it is smaller than both children.
>
> Thus, after either operation, the root remains the minimum element.
>
> ### Shape property
>
> - `insert` always adds to the subtree with fewer nodes, ensuring that the left subtree has either the same number of elements as the right subtree or one more.
> - `remove_last` removes from the subtree containing the rightmost deepest node, preserving left-completeness.
>
> Hence the shape invariant is maintained.
>
> ---
>
> ## Complexity
>
> Let $n$ be the number of elements.
>
> - `min`: $O(1)$
> - `empty`: $O(1)$
> - `insert`: $O(\log n)$
> - `delete_min`: $O(\log n)$
>
> since each operation follows a single root-to-leaf path in a balanced complete tree.
>
> ---
>
> ## Final answer
>
> A correct OCaml solution is to represent the heap as a left-complete binary tree storing subtree sizes, and implement:
>
> - `empty` as `Empty`,
> - `min` by returning the root value,
> - `insert` by inserting into the smaller subtree and bubbling up,
> - `delete_min` by removing the last element, placing it at the root, and sifting down.
>
> The complete implementation is the code given above.
